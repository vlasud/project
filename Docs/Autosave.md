# Автосейв онлайн-игроков (Autosave)

Код: `Src/Systems/AutosaveSystem` (таймер + проход по онлайну),
`Src/Services/PlayerSessionService` (канал `subscribeSave` / метод `save`).

## Что это

Периодический автосейв аккаунт-данных ОНЛАЙН-игроков. Раз в `AUTOSAVE_INTERVAL`
проходит по всем подключённым игрокам с активной сессией и прогоняет save-канал
`PlayerSessionService` — идемпотентный снимок состояния в БД (без завершения
сессии).

## Зачем

open.mp на **штатной остановке** сервера НЕ диспатчит `onPlayerDisconnect`
(подтверждено по исходникам: `~Core → players.free()` освобождает игроков без
события дисконнекта). Значит `PlayerSessionService::end()` и через него
session-end-персист для остававшихся онлайн игроков **не срабатывают** — их
изменения за сессию (вещи, прокачка оружия, личный скин) в БД не уходят.

Автосейв ограничивает потерю **интервалом** и заодно покрывает **краш** сервера
(там события дисконнекта тоже нет).

**Zero-loss на штатном стопе НЕ гарантируется.** Гарантированная нулевая потеря
потребовала бы shutdown-flush: в `GameMode::free()` до `ThreadPool::shutdown`
форсить персист онлайн-игроков и синхронно дренировать backpressure-очереди
`DatabaseManager` (хрупко: после join воркеров перезапущенные задачи не
выполнятся). Это отложено намеренно — автосейв проще и закрывает основную потерю.

## Как

### Канал `subscribeSave` (PlayerSessionService)

Три РАЗНЫХ канала подписок с разной семантикой:

| Канал | Когда зовётся | Семантика | Кто подписан |
|----|----|----|----|
| `subscribeStart` | старт сессии | загрузка данных аккаунта (async-select + serial-guard) | загрузчики |
| `subscribeSave` | конец сессии (внутри `end`, ДО teardown) **И** автосейв (`save`) | идемпотентный снимок/UPSERT по `account_id` | **только персистеры** |
| `subscribeEnd` | **только** конец сессии (`end`), НЕ автосейв | teardown памяти / сброс слотов | **только деструктив** |

`end()` гонит каналы строго в порядке: сперва `m_saveObservers` (персист), затем
`m_endObservers` (teardown). Teardown сбрасывает членство/админку в памяти — он не
должен предшествовать снимку, иначе персист сохранил бы уже обнулённое.

`save(player)`: если сессия активна — копирует `Session` по значению и прогоняет
ТОЛЬКО `m_saveObservers`, не трогая `m_online` / `Session` (сессия продолжается).
Offline/без сессии — ранний return.

### Кто переиспользует save-канал, а кто исключён

В save-канал перенесены ТОЛЬКО идемпотентные персистеры (повтор по `account_id`
безвреден):

- `InventorySystem::persistItems` — REPLACE снимка `player_items` (транзакция);
- `WeaponProficiencySystem::persistProficiency` — UPSERT `player_weapon_skill`;
- `PlayerPersonalSkinSystem` — UPDATE `player.skin`.

**Исключены (остаются на `subscribeEnd`, автосейвом НЕ гоняются):**

- `FactionSystem` — `resetPlayer()`: сброс членства В ПАМЯТИ (членство пишется в БД
  write-through сразу при изменении; конец сессии БД не трогает);
- `AdminSystem` — `reset()` + сброс saved-locations / pending: чистый сброс памяти.

Если бы они попали в save-канал, автосейв периодически **обнулял бы членство во
фракции и вход в админку** у онлайн-игроков. Поэтому канал разведён, а не
переиспользован end.

### AutosaveSystem

- Зависимости: `PlayerSessionService`, `TimerService`.
- Таймер ставится в `initialize()` (не в конструкторе): к этому моменту
  `TimerSystem` уже передал сервису компонент таймеров. Хэндл хранится в члене,
  отмена не нужна (живёт всю работу сервера).
- Регистрируется ПОСЛЕ `PlayerSessionSystem` и всех save-подписчиков, чтобы к его
  `initialize()` все персистеры уже подписались в своих конструкторах.
- `saveAll()`: проход по `getPlayers().entries()`; для каждого, у кого
  `isActive(id)`, — `save(*player)`.

## Баланс-константы

`Src/Systems/AutosaveSystem/AutosaveSystem.h`:

| Константа | Значение | Смысл |
|----|----|----|
| `AUTOSAVE_INTERVAL` | 2 мин | период автосейва; меньше — меньше потеря, выше всплеск БД-записей |

## Анти-чит / краш-безопасность / перф

- **Абьюз.** Внутренний периодический процесс, клиентского ввода нет. Персисты
  идемпотентны (REPLACE/UPSERT по `account_id`) — повтор безвреден. Ключевое:
  Faction/Admin вне save-канала — иначе автосейв рушил бы членство/админку.
- **Краш/UB.** `saveAll` итерирует валидных игроков из пула; `save()` гардится
  `isActive` (бот/не залогиненный — no-op); каждый персистер гардится своим
  `m_loaded` (автосейв только-что-зашедшего, чья загрузка не дошла, не затрёт БД).
  Таймер на главном потоке, разыменования невалидных игроков нет.
- **Перф.** Раз в 2 мин, не per-tick. Всплеск БД-записей при большом онлайне
  приемлем (записи уходят на воркеры `DatabaseManager`); при необходимости позже
  размазать (stagger) по тикам — пока намеренно не усложняем.
