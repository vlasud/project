# Работа водителя автобуса (BusJob)

Бизнес-фича (НЕ Core). Вторая «работа» по паттерну порта. Код:
`Src/Services/BusJobService` (источник правды — пер-player фаза смены/прогресс
маршрута + состояние 3 ФИЗИЧЕСКИХ площадок депо + FIFO-очередь),
`Src/Services/BusWalletService` (источник правды — ПЕРСИСТЕНТНЫЙ per-account
кошелёк заработка, write-through в БД; дословный близнец `PortWalletService`, иная
таблица), `Src/Systems/BusJobSystem` (привод: пикап, диалог, спавн/деспавн
автобусов, пере-сток депо, race-чекпоинты маршрута, общий таймер депо,
начисление/выдача денег, гейт водителя).

## Правило владельца (привязка ТОЛЬКО руля)

Привязан **только руль**. За руль закреплённого за работником автобуса
(`Reserved`/`Driving`) может сесть **ТОЛЬКО он**. За руль незарезервированного стоящего
pre-stock автобуса **не садится НИКТО** (ждёт резерва). **Пассажирские места СВОБОДНЫ
ДЛЯ ВСЕХ** у любого автобуса — стоящего, зарезервированного и едущего по маршруту (это
автобус, пассажиры у него могут быть). **Замков дверей и высадки пассажиров НЕТ** —
двери всем открыты, гейтится исключительно место водителя.

Привязка держится **одним слоем — серверным гейтом водителя**
(`subscribeDriverGate` → `onDriverGate`, по occupant-трекингу `VehicleService`, не по
клиенту): игрок стал водителем не своего автобуса → гейт возвращает `false`, и
`VehicleService` немедленно **высаживает** его (`removeFromVehicle`, force — отменяет и
уже занятое место, и незавершённый вход) + сообщение. Пассажирских мест гейт **не
касается** — они свободны. Клиентских `params.doors`-замков у работы нет.

Свой автобус помечен **красным маркером**; **перенос резерва убран** — сесть за руль
можно ТОЛЬКО в него. Ветка **detached reserved** (увёл свой автобус с площадки, не взяв
первый чекпоинт) рабочая: **вернуться за руль СВОЕГО автобуса можно всегда** (ветка
`workerOfVehicle == playerId` гейта водителя).

Автобусы существуют ТОЛЬКО под работу — нет ни одного постоянного автобуса. В депо
ВСЕГДА стоят 3 незарезервированных (pre-stock) автобуса модели 431; водитель
угоняет один на маршрут, депо доспавнивает новый на освободившуюся точку.
**Занятость площадки — ФИЗИЧЕСКАЯ**: точка занята, пока на ней стоит рабочий
автобус; уехал — точка свободна и пере-стокуется. `SLOT_COUNT` (3) — размер депо
(пропускная способность старта), а НЕ потолок одновременных водителей: их на
маршруте может быть сколько угодно.

## Петля

1. Игрок встаёт на **пикап трудоустройства** (фикс. серверная точка) → диалог
   `DialogStyle_LIST` с четырьмя пунктами (порядок как у порта): «Начать работу»,
   «Завершить работу», «Забрать деньги», «Информация». **Все пункты видны ВСЕГДА** —
   недоступность объясняется сообщением по клику, а не скрытием (правило проекта).
2. **«Начать работу»** (гейт: залогинен, `PlayerState_OnFoot`, ещё НЕ в смене/очереди) →
   - **Невозвратный вступительный взнос `BUS_JOB_ENTRY_FEE` ($1000) НАЛИЧНЫМИ**
     (`PlayerMoneyService`, НЕ кошелёк работы). Проверка наличия и списание —
     **атомарно** в момент клика и **ДО** перевода в работники (сначала успешное
     списание, потом смена фазы — иначе при нехватке денег повисла бы фаза).
     Не хватает → **отказ** («Недостаточно наличных: вступительный взнос $1000 (у
     вас $N)»), игрок **НЕ становится работником и НЕ встаёт в очередь**. Списалось →
     обязательное сообщение в чат («Вступительный взнос $1000 списан (не возвращается)»),
     дальше распределение:
   - Есть **свободный стоящий автобус** в депо → он **закрепляется** за игроком
     (фаза `Reserved`), показывается первый чекпоинт, стартует окно посадки; игроку
     сообщение в чат + попап. **Автобус НЕ спавнится под заказ — он уже стоит.**
   - **Свободных стоящих нет** (все закреплены/угнаны) → фаза `Queued`, игрок ждёт
     (сообщение «Свободных автобусов в депо сейчас нет. Вы в очереди, место N»). При
     каждом сдвиге очереди ждущим шлётся обновлённое место (`notifyQueueShift`),
     голове — «вы следующий».

   **Взнос — денежный сток (барьер входа):** назад НЕ возвращается **никогда** — ни
   штатное увольнение, ни смерть, ни дисконнект, ни провал посадки денег не трогают.
   Берётся **ОДИН раз при новом устройстве** (переход `NotWorking → работник`); диалог
   «Начать работу» сам по себе НЕ подтверждающий — списание по клику пункта. **Провал
   посадки** возвращает в конец очереди работником (`failBoarding`, фаза `Queued`) —
   взнос **повторно НЕ берётся**; новый взнос только при новом устройстве после конца
   смены. Уже работающему/стоящему в очереди клик «Начать работу» → отказ «Вы уже
   работаете…» **без списания** (гейт `isWorking` до денег).
3. **Резерв и посадка (30 с).** Автобус закреплён за работником — сесть в него может
   ТОЛЬКО он (см. «Правило владельца»); в **свободный стоящий** pre-stock — **никто**
   (перенос резерва убран). С момента резерва у игрока `RESERVE_SECONDS` секунд, чтобы
   **сесть за руль И подобрать первый чекпоинт** (`onCheckpointEnter` за рулём →
   `completeBoarding`, `Reserved → Driving`). Не успел (`failBoarding`) → работник в
   **конец очереди**; автобус: **так и стоит нетронутым на площадке** → остаётся
   стоять свободным pre-stock (не деспавним, резерв снят); **уведён с площадки** →
   деспавн (хлам не бросаем). Лимита провалов нет.

   **Маркер зарезервированного автобуса.** В момент резерва (`onReserved`) игроку
   ставится **красный чекпоинт-указатель на его автобус** (найти свой среди трёх
   стоящих) через общий `VehicleWaypointService::showFor(player, bus)` — тот же
   механизм, что ведёт к вызванной машине у парковки/`/car`. Ставится вместе с
   GUI-таймером `BOARDING` и первым race-чекпоинтом маршрута; **все три
   сосуществуют** — указатель в **обычном** клиентском слоте чекпоинта, маршрут в
   **race-слоте** (`CheckpointService` держит их раздельно). **Снимается**, как только
   игрок **сел за руль своего автобуса** (`onDriverGate`, ветка `worker == playerId` —
   `clearFor`), а также при **провале посадки**
   (`failBoarding`), **любом увольнении** (`teardownShift`) и **дисконнекте**
   (`onSessionEnd → teardownShift`, плюс собственный сброс `VehicleWaypointSystem` на
   `onPlayerDisconnect`) — не залипает ни на одном пути.

   **Конфликт обычного слота (семантика «последний выигрывает»).**
   `VehicleWaypointService` — **один слот на игрока** (клиент показывает лишь один
   обычный чекпоинт); указатель парковки (вызвал личную машину) и маркер автобуса
   делят этот слот. Пере-вызов `showFor` **перетирает** прежний указатель: если у
   игрока висел маркер парковки, резерв автобуса заменит его на автобус, и наоборот —
   более поздний указатель выигрывает (утечки/краша нет: старая цель просто забывается,
   `findByVehicle` её больше не матчит). Симметрично снятие маркера автобуса
   (посадка/провал/увольнение) гасит текущий обычный слот целиком — если игрок УСПЕЛ
   после резерва поставить указатель парковки, тот тоже погаснет (редкий угловой
   случай, принятый компромисс единого слота).
4. **Маршрут.** 54 race-чекпоинта по кругу; после последнего — снова первый,
   бесконечно. Зачёт **ТОЛЬКО за рулём СВОЕГО** автобуса (пешком/на другом ТС не
   триггерит).
   - **move**: подобрал (вход за рулём) → зачёт СРАЗУ, следующий;
   - **stop** (остановка): **простоять `STOP_DWELL_SECONDS` секунд** в зоне за рулём
     (по **принятой сервером позиции**; уехал раньше — счётчик сброшен) → зачёт,
     следующий.

**Визуал чекпоинтов маршрута.** Цель показывается **race-чекпоинтом**
(`CheckpointService::setRaceForPlayer`, отдельный клиентский слот — на обычный
персональный чекпоинт, напр. красный чекпоинт парковки, не влияет и им не перетирается):
   - **move** → `RACE_NORMAL` со **стрелкой на следующую точку маршрута** (по кругу:
     после 54-й — 1-я) — водитель всегда видит, куда ехать дальше;
   - **stop** → `RACE_FINISH` **без стрелки** (финиш-маркер «здесь стоим»); nextPosition
     передаётся пустым `(0,0,0)`, иначе клиент показал бы стрелку (`RACE_NORMAL`).

Радиусы (`MOVE_CP_RADIUS` / `STOP_CP_RADIUS`) сохранены: open.mp шлёт `size = radius`
одинаково для обычного и race-чекпоинта (`checkpoint.hpp`), пересчёта диаметр/радиус не
требуется — прежний видимый размер и зона зачёта не изменились. Вся dwell-логика
остановки (10 с в зоне за рулём, выезд сбрасывает таймер) и правила зачёта — **без
изменений**, поменялся только вид чекпоинта.
5. **Деньги.** Каждый зачтённый чекпоинт → **`PAY_PER_CHECKPOINT` ($50) СРАЗУ** в
   кошелёк (`BusWalletService::add`, write-through в БД). Полный круг (54 подряд) →
   дополнительно **`LAP_BONUS` ($2000)** туда же.
6. **Топливо.** Каждый автобус депо получает **бесконечное топливо**
   (`VehicleService::setInfiniteFuel(true)` сразу после спавна): бак не расходуется и
   держится полным, автобус **не может заглохнуть от пустого бака**. Своей топливной
   логики (дренаж/глушение/заправка) у работы нет — заправка на круге убрана как
   лишняя, «пустой бак посреди круга» недостижим.
7. **Посадка завершена → выезд на маршрут.** `completeBoarding` (`Reserved →
   Driving`): автобус **покидает депо** (становится личным едущим), его площадка
   **освобождается и пере-стокуется** (новый pre-stock, как только точка физически
   чиста). Водителей на маршруте одновременно — **сколько угодно**.
8. **Прерывание смены.** Вышел из автобуса в смене → `RETURN_SECONDS` (30 с) вернуться
   за руль, иначе увольнение. **Анти-AFK за рулём:** сидит за рулём, но за
   `NO_PROGRESS_SECONDS` (240 с) не зачёл ни одного чекпоинта → предупреждение за 30 с,
   затем увольнение (чтобы не копить брошенные машины на маршруте). **Смерть**
   (`PlayerHealthService::subscribeDeath`) / **дисконнект** (`subscribeEnd`) →
   увольнение сразу. **«Завершить работу»** у пикапа → штатное увольнение.
   **Увольнение/дисконнект деспавнит едущий/уведённый автобус** (резервный, так и
   стоящий на площадке, — оставляет pre-stock), **кошелёк НИКОГДА не трогает.**
9. **«Забрать деньги»** (доступно всегда) → весь кошелёк на руки
   (`PlayerMoneyService::giveMoney`), обнуление. Кошелёк переживает смерть,
   увольнение, дисконнект и рестарт (БД).

## Экранный таймер (GUI-бар обратного отсчёта)

Три временны́х окна смены дублируются **экранным таймером-баром** (Core-сервис
`ScreenTimerService`, верх-центр экрана, см. `Docs/ScreenTimer.md`). Остаток пушится
из **существующего per-second тика депо** — **новых таймеров не заводится**, источник
правды о времени остаётся у BusJob (серверные счётчики окон). Метки — **English**
(`BOARDING` / `RETURN` / `BUS STOP`), остаток числовой `M:SS`.

| Окно | show | обновление | hide |
|---|---|---|---|
| **Посадка** (`BOARDING`, `RESERVE_SECONDS`) | при резерве (`onReserved`, полный остаток) | каждую секунду в `tickWorker` (фаза `Reserved`) | завершение посадки (`onCheckpointEnter` → `completeBoarding`) / провал (`failBoarding`) / увольнение (`teardownShift`) |
| **Возврат** (`RETURN`, `RETURN_SECONDS`) | первый тик вне руля своего автобуса в смене | каждую секунду в `tickWorker` (Driving, не за рулём) | возврат за руль (следующий тик за рулём) / увольнение (`teardownShift`) |
| **Остановка** (`BUS STOP`, `STOP_DWELL_SECONDS`) | вход в stop-чекпоинт (`onCheckpointEnter`, полный остаток) | каждую секунду в `tickWorker` (dwell по принятой позиции) | выезд из зоны (сброс dwell → `hide`, вернётся при заезде) / зачёт (`creditAndAdvance`) / увольнение |

Один слот на игрока (`ScreenTimerService`) — окна не пересекаются во времени в рамках
одной смены, показ следующего окна перекрывает бар предыдущего.

**Попап «bus stop - wait Ns» УБРАН** (вердикт геймдизайнера): его единственное
содержимое — длительность простоя — теперь несёт бар `BUS STOP 0:10` живым отсчётом,
а не статичным «10s»; на въезде в stop-чекпоинт больше нет дубля из двух экранных
сигналов. Чат-подсказка остановки (инструкция «постойте 10 секунд…») сохранена.

**Остальные ScreenNotice-попапы (низ-право) и чат-подсказки НЕ тронуты** (иной слот,
иной сервис): «bus reserved - get in and drive» (команда к действию), «boarding failed
- back to queue» (исход), наградные попапы, чат-сообщения о резерве/остановке/провале/
зачёте остаются как были — таймер-бар их **дополняет** (правило: бар = сколько
осталось, попап = разовый исход/награда/команда к действию, чат = инструкция+RP).
Анти-AFK-предупреждение (210 с) таймером **не** отображается (вне объёма).

## Устройство: депо, площадки, резерв, очередь

`BusJobService` — источник правды:

- **3 площадки** (`m_spots[SLOT_COUNT]`, поле `Spot{vehicleId, reservedBy}`): на
  каждой либо стоит автобус депо (`vehicleId >= 0`) — свободный pre-stock
  (`reservedBy == -1`) или закреплённый за работником (`reservedBy == playerId`) —
  либо площадка пуста (`vehicleId == -1`, ждёт пере-стока).
- **Пер-player стейт** (`State{phase, vehicleId, cpIndex}`): фаза цикла, id
  закреплённого/угнанного автобуса, индекс чекпоинта. Резервный автобус числится И
  за площадкой (`reservedBy`), И в стейте игрока (`vehicleId`); угнанный (Driving) —
  только в стейте (площадку уже отпустил).
- **FIFO-очередь** (`std::deque<int> m_queue`): работники без стоящего автобуса.

**Пере-сток и занятость — ФИЗИЧЕСКИ** (`BusJobSystem::restockDepot`, тик депо):

- Занятость точки для пере-стока — **многопробный** критерий `BusJobSystem::spotClear`,
  как `ParkingSystem::isSpotFree`: центр + пробы «вперёд»/«назад» вдоль ориентации места
  (`SLOT_ANGLE`, `Geometry::forwardOf`/`backOf`), каждая — `anyVehicleNear` радиусом
  `SPOT_OCCUPIED_RADIUS` (горизонтальный XY, Z игнорируется, пространственный индекс
  `GridService`). Автобус длинный (~13 м) — пробы вдоль оси места ловят его **телом**, а
  не только origin'ом; пробы идут ⊥ ряду площадок (тело вдоль Y, соседи по X ~7.09 м) →
  кросс-детекта соседних автобусов нет. Заблокирована посторонним транспортом (или
  вернувшимся рабочим автобусом) → занята, новый НЕ спавнится.
- Площадка с автобусом: если он **физически уехал** с точки (`busOnSpot` — дистанция²
  ОРИГИНА автобуса до `SLOT_POS[i]` > `SPOT_RADIUS²`) ИЛИ **исчез из пула** — привязка снимается
  (`clearStanding`). Уехавший **резервный** оставляем (им владеет игрок через стейт).
  Уехавший **pre-stock** (за руль его легально никто не берёт — взявший работник тут
  же перевёл бы его в reserved) считается **сдвинутым тараном/глитчем** и деспавнится
  (не копим «призраки» в мире).
- Пустая площадка + точка физически чиста → спавн нового pre-stock
  (`spawnPrestock`, `VehicleService::create`, `Owner::Work`, ownerId `-1`). Пул полон
  → повтор на следующем тике. 3 стартовых автобуса — в `initialize` (та же логика).
  Каждый заспавненный автобус сразу получает `setInfiniteFuel(true)` — это
  **единственный путь спавна** автобусов, другого нет.

**Резерв** (`startWork`/`promoteQueue`): свободный стоящий автобус закрепляется за
работником (`reservedBy`, фаза `Reserved`, `state.vehicleId` = id этого автобуса).
Спавна нет. Голова очереди продвигается на каждый освободившийся стоящий автобус
(пере-сток/снятый резерв) в **тике депо** (`pumpQueue`, до `SLOT_COUNT` продвижений
за тик).

**Гейт посадки — только руль** (см. «Правило владельца»). Один слой — **гейт водителя**
(`onDriverGate`), дешёвый ранний выход на `Owner != Work` (личные/фракционные/парковка
— без скана):

- наш автобус резервный/едущий → только его работник (`workerOfVehicle`, скан по
  стейту), чужой резервный/едущий → отказ;
- свободный стоящий pre-stock → **отказ всем** (перенос резерва убран; работнику в фазе
  `Reserved` — подсказка «ваш автобус отмечен маркером»);
- **Исключение «detached reserved»**: резервный автобус работника уже уведён с площадки
  (пере-сток снял `reservedBy`, но `state.vehicleId` держит тот автобус) — за руль
  **своего** уведённого автобуса работника пускает ветка `workerOfVehicle == playerId`
  (вернуться за руль своего можно всегда).

При отказе гейта `VehicleService` сам **высаживает** игрока
(`removeFromVehicle`, force) — серверный бэкстоп по факту посадки (occupant-трекинг),
клиенту не верим. **Пассажирские места гейт НЕ трогает** — они свободны для всех.
Клиентских `params.doors`-замков (`setLockedForPlayer`) и высадки пассажиров у работы
нет; примитив замка дверей остаётся у личных машин (`VehicleLockService`) и с рабочими
автобусами не пересекается.

## Таймер депо (один общий, per-second)

**Один общий `TimerService::setInterval(1s)`** на весь сервер (`m_depotTimer`,
создаётся в `initialize`, **никогда не отменяется**, в т.ч. из своего колбэка).
`onDepotTick` в порядке:

1. `restockDepot` — реконсиляция/пере-сток 3 площадок. `O(SLOT_COUNT)`, дешёвые
   проверки (`busOnSpot`/`spotClear` — до 3 проб `anyVehicleNear` на площадку), без аллокаций.
2. `pumpQueue` — продвижение очереди на освободившиеся стоящие автобусы (≤ `SLOT_COUNT`
   итераций).
3. `tickActiveWorkers` — окна активных работников (`Reserved`/`Driving`): обход онлайна
   (`getPlayers().entries()`), тикаются только они. `O(активных водителей)` — водителей
   не ограничиваем, per-worker работа дешёвая (счётчики + разовые проверки).

`tickWorker` по фазе:

- `Reserved`: `++reserveSeconds`; `>= RESERVE_SECONDS` → `failBoarding`.
- `Driving` + за рулём своего автобуса: `exitSeconds = 0`; `++idleSeconds` (анти-AFK):
  `== NO_PROGRESS_WARN_SECONDS` → предупреждение, `>= NO_PROGRESS_SECONDS` → увольнение;
  сбрасывается на каждом зачёте. Текущий чекпоинт `stop` И принятая позиция в зоне
  `STOP_CP_RADIUS`: `++dwellSeconds`; `>= STOP_DWELL_SECONDS` → зачёт.
- `Driving` + НЕ за рулём своего автобуса: `dwellSeconds = 0`; `++exitSeconds`;
  `>= RETURN_SECONDS` → увольнение.

Секундная гранулярность (`±1 с`) для окон 10/30/240 с несущественна. Вновь
продвинутый в этом же тике работник максимум теряет 1 с окна — тоже несущественно
(снимок для депо-части не нужен: работников не итерируем по площадкам).

## Кошелёк автобусника (персист)

`BusWalletService` — точная копия `PortWalletService`, таблица `bus_wallet`:

- `add(playerId, accountId, amount)` — кэш `+= amount`, затем write-through UPSERT.
  `amount <= 0` / `NO_ACCOUNT` / bounds-промах — no-op.
- `withdraw(playerId, accountId)` — **кэш обнуляется СРАЗУ** (анти-дюп двойного
  клика), затем write-through **относительным** списанием. Возвращает сумму; `0` —
  нечего/`NO_ACCOUNT`.
- `load`/`reset` — только память, лайфцикл сессии.

**Загрузка по сессии** — `subscribeStart` → async `selectQuery<std::int64_t>` →
**serial-guard** → `load`. `subscribeEnd` → `reset` (только ОЗУ-кэш, баланс в БД
остаётся до явного «Забрать деньги»).

## Дефолты (решения геймдизайна)

- **Занятость площадки — физическая** (стоит ли автобус), а не «числится смена».
  Driving-водитель площадку НЕ держит → водителей на маршруте не ограничено.
- **В депо всегда стоят 3** незарезервированных автобуса; пере-сток — по факту
  физической чистоты точки.
- **Лимита провалов посадки нет.**
- **Вступительный взнос $1000 наличными, невозвратный** — барьер входа и денежный
  сток. Списывается один раз при новом устройстве (не при повторной постановке в
  очередь после провала), назад не возвращается ни в одном исходе смены; кошелёк
  работы (`bus_wallet`) взносом не трогается.
- **Маркер зарезервированного автобуса** — красный чекпоинт-указатель на закреплённый
  автобус (общий `VehicleWaypointService`, обычный слот, сосуществует с race-маршрутом);
  снимается на посадке за руль/провале/увольнении/дисконнекте. Единый слот на игрока —
  указатель парковки и маркер автобуса делят его (последний выигрывает).
- **Топливо**: **бесконечное** у каждого автобуса депо (`VehicleService::setInfiniteFuel`)
  — бак не расходуется и держится полным, автобус не глохнет от пустого бака; своей
  топливной логики (дренаж/заправка) у работы нет.
- **Смерть/дисконнект = увольнение сразу**; кошелёк переживает всё.
- **Рабочий скин НЕ форсится.**

## Три правила

- **Читер-абуз:** занятость площадки и пере-сток — **серверный расчёт**
  (`anyVehicleNear`/`busOnSpot` по серверным позициям машин, клиент на них не влияет);
  спавн/деспавн — только `VehicleService`. **Привязка руля — серверный гейт водителя**
  по факту посадки (occupant-трекинг `VehicleService`, не клиент): не пускает чужого за
  руль резервного/едущего автобуса и **отказывает всем** за руль стоящего pre-stock
  (перенос резерва убран — за руль своего отмеченного маркером автобуса пускает только
  ветка `workerOfVehicle == playerId`). При отказе `VehicleService` немедленно
  **высаживает** игрока (`removeFromVehicle`, force) — читеру не сесть за руль, даже
  минуя клиентский вход. **Пассажирские места свободны для всех** (это автобус) — гейт
  их не трогает, замков дверей нет. Сдвинутый тараном pre-stock деспавнится (нет
  «ничьих» рабочих автобусов в мире). Зачёт чекпоинта — ТОЛЬКО «за рулём своего
  автобуса» (серверный `getDriver`), вход валидируется `CheckpointService` по принятой
  позиции, stop-простой — по принятой позиции в зоне.
  «Начать работу» гейтится серверным `PlayerState_OnFoot`; деньги — только `add` по
  серверному факту зачёта, `add`/`withdraw` no-op без `accountId`, `withdraw` обнуляет
  кэш СРАЗУ; попапы лишь отражают серверные суммы. **Вступительный взнос** проверяется
  и списывается против **серверного баланса** (`PlayerMoneyService::getMoney/setMoney`,
  НЕ клиентский HUD), атомарно и ДО перевода в работники; взнос берётся ровно один раз
  на устройство (гейт `isWorking` до денег — ни повтор клика, ни возврат из очереди
  после провала не спишут второй раз и не устроят «бесплатный» вход). **Маркер
  автобуса** ставится по серверной позиции автобуса (`VehicleWaypointService` →
  `CheckpointService` с валидацией входа по принятой позиции) и снимается по серверным
  событиям (гейт водителя/провал/увольнение/дисконнект), клиент на него не влияет.
  Векторы закрыты: фарм пешком/на чужом ТС, телепорт на чекпоинт, **угон стоящего/
  резервного/чужого автобуса за руль** (в т.ч. попытка сесть за руль минуя клиентский
  вход — серверная высадка), дюп при «Забрать деньги», начисление без сессии,
  **утечка/«призраки» рабочих машин**, **обход/двойное списание вступительного взноса**.
  Пассажирские места намеренно **открыты всем** — это автобус, вектора «пассажир» тут
  нет.
- **Краш-безопасность:** все входы `BusJobService`/`BusWalletService` bounds-safe по
  `playerId`/`spot` (`Spot`/`State` value-init с `-1`, playerId 0 валиден); async-колбэки
  БД и колбэки диалога/чекпоинта заново резолвят живого игрока и не разыменовывают
  невалидного; тик депо обходит онлайн (`entries()`), null-гардит игрока и bounds
  `playerId`; спавн/деспавн внутри тика не трогают сам таймер и не мутируют пул
  игроков (ре-энтрантности нет); `teardownShift` снимает состояние сервиса ДО `destroy`
  автобуса; **деспавн едущего/уведённого автобуса гарантирован во ВСЕХ выходах смены**
  (увольнение/провал/смерть/дисконнект/анти-AFK) — утечки нет; кошелёк в БД конец
  сессии НЕ трогает; write-through каждого зачёта; serial-guard загрузки; общий
  таймер НИКОГДА не отменяется (в т.ч. из своего колбэка).
- **Перф:** геймплей событийный (пикап/чекпоинт/клик диалога) + ОДИН общий per-second
  таймер депо: депо-часть `O(SLOT_COUNT)` дешёвых проверок без аллокаций, продвижение
  очереди ≤ `SLOT_COUNT`, окна работников `O(активных водителей)` с per-worker
  дешёвой работой; гейт водителя — ранний выход по owner-тегу (`O(1)` для не-рабочих
  машин), скан по стейту/площадкам только для `Owner::Work`; `balanceOf`/`phaseOf` —
  чтение кэша; БД-запросы кошелька — асинхронные; спавн/деспавн и `notifyQueueShift`
  (`O(длины очереди)`) — холодный путь, не per-tick. **GUI-таймер-бар** пушится из
  того же per-second тика (новых таймеров нет): у игроков с активным окном — один
  SetString RPC + локальная строка `fmt`, у прочих `hide()` скрытого бара — no-op
  (`O(активных окон)`).

Прервать смену можно и **издалека, из любой точки** — командой `/stopjob` (диалог с
предупреждением, увольняет тем же обработчиком «Завершить работу»). См.
`Docs/StopJob.md`.

Сколько накоплено, видно в общем списке `/jobwallet` (напоминание в чат на входе, если
в кошельках что-то есть). Забирают деньги ТОЛЬКО здесь, у пикапа работы —
`/jobwallet` лишь справка. См. `Docs/JobWallet.md`.
