# Меню личного транспорта (`/car`)

`/car` — бизнес-фича (НЕ Core): двухуровневое меню личного транспорта игрока. Код:
`Src/Systems/CarMenuSystem`. Собственного сервиса нет — источник владения —
`PersonalVehicleService`, о машинах — `VehicleService`, парковка у дома —
`ParkedVehicleService`, замок дверей — `VehicleLockService` (`Docs/VehicleLock.md`),
красный чекпоинт-указатель — общий `VehicleWaypointService`.

## Корень `/car`

**LIST-диалог** «Личный транспорт»: `Текущая машина` / `Мои машины`. Кнопки —
слева `Выбрать`, справа `Закрыть` (корень без родителя).

```
Текущая машина
Мои машины
```

## Раздел 1 — «Текущая машина»

**Гейт при выборе пункта** (пункт видим ВСЕГДА — правило видимости; гейт срабатывает
в обработчике клика, не в построении меню): игрок сидит В СВОЕЙ машине (любое
сиденье, не только водитель) — `CarMenuSystem::ownCurrentVehicle`:

- **личная сессионная** — `VehicleService::getOwner == Owner::Player` И `getOwnerId
  == playerId` (серверный тег, не клиент);
- **ЛИБО припаркованная ИМ** — `VehicleService::getVehicle(playerId)->getID()` есть в
  `ParkedVehicleService::byVehicleId`, и `parked->ownerAccountId == accountId`
  сессии (`PlayerSessionService::getAccountId`).

Расшаренная семье машина ЧУЖОГО владельца (сам игрок — просто член семьи, не
владелец) — **НЕ своя**: сидя в ней, «Текущая машина» откажет. Не в своей машине —
`Вы не в своей машине` (ERROR) + выход, диалог НЕ открывается.

### Под-меню «Текущая машина» (`DialogStyle_LIST`)

Заголовок — имя машины (`VehicleModelNames::displayName`). Кнопки: `Выбрать` /
`Назад` (-> корень). Три пункта, лейблы динамические по ТЕКУЩЕМУ состоянию
(`vehicle.getParams()`/`VehicleLockService::isLocked` на момент показа):

| Пункт (лейбл зависит от состояния) | Источник состояния | Действие |
|---|---|---|
| `Завести двигатель` / `Заглушить двигатель` | `params.engine` (`!= 0` — «работает», как тумблер клавиши) | `VehicleService::setEngine` |
| `Включить фары` / `Выключить фары` | `params.lights` (только явная `1` — «включены») | `VehicleService::setLights` |
| `Закрыть двери` / `Открыть двери` | `VehicleLockService::isLocked` | `VehicleLockService::toggle` |

**Отказы двигателя ОДИНАКОВЫ с клавишным тумблером — тот же попап, не чат.**
Обе причины идут через общий `VehicleEngineNotice` (единый источник текста/цвета/
длительности, `Src/Systems/Core/VehicleControlSystem/VehicleEngineNotice.h`) поверх
`ScreenNoticeService`: `engine is broken` (красный, `isStalled`) / `no fuel`
(жёлтый, `isOutOfFuel`), 3 с — БАЙТ-В-БАЙТ то же, что видит игрок при нажатии
клавиши (см. `Docs/VehicleControls.md`). Одна причина — одна обратная связь,
независимо от того, откуда пришёл отказ (клавиша или меню). После попапа под-меню
переоткрывается с обновлёнными лейблами. Заглушить можно всегда.

**После КАЖДОГО действия**: сообщение в чат об итоге + под-меню «Текущая машина»
ПЕРЕОТКРЫВАЕТСЯ с обновлёнными лейблами (удобно щёлкать несколько тумблеров
подряд без выхода в корень). Обработчик КАЖДОГО клика заново зовёт
`ownCurrentVehicle` — диалог мог провисеть, пока игрок вышел из машины или она
исчезла (уничтожена извне); в этом случае — тот же отказ `Вы не в своей машине`,
без падения.

Замок — `Docs/VehicleLock.md` (пер-игровой, НЕ глобальный `setLocked` — иначе
владелец запер бы сам себя снаружи).

## Раздел 2 — «Мои машины»

**Список** — `DialogStyle_TABLIST_HEADERS` (образец —
`WeaponProficiencySystem::showSkills`, индексация строк без сдвига на шапку —
`FactionSystem::showMembersMenu`): колонки `Машина` / `Где находится`. Пустое
владение -> сообщение в чат, В ДИАЛОГ НЕ ЗАХОДИМ (как раньше):

```
Машина            Где находится
Infernus          на парковке
Sultan            у дома
Bobcat            Lo_Vlasud[12]
```

`{имя}` — `VehicleModelNames::displayName(model)` (фолбэк `Модель {id}` для битой
модели). `{где}` — единый словарь `placementStatus` (тот же, что у центральной
парковки): `у дома` (припаркована лично) / `в семье` (припаркована и расшарена) /
`на парковке` (`vehicleId == -1`, не в мире — взять на центральной парковке) /
`вызвана` (`vehicleId != -1`, в мире).

**Оверлей водителя (только в этом списке):** если за рулём живого экземпляра
кто-то сидит (`VehicleService::getDriver != -1`) — колонка показывает КТО вместо
статуса: `{ник}[{playerId}]` (пример: `Lo_Vlasud[12]`). Владельцу важнее «кто
сейчас в моей машине», чем режим размещения; когда водитель выйдет — статус
вернётся. Водитель — серверный источник (`getDriver`), ник строго латиница
(`NicknameService`): без `\t`/`\n`/`{}` — безопасен для tablist-строки, `u()` его
не меняет. Список центральной парковки оверлей НЕ показывает (там выбирают, что
взять, а припаркованные/занятые всё равно не берутся) — базовый словарь общий.
Кнопки: `Выбрать` / `Назад` (-> корень `/car`).

### Под-диалог действий (`DialogStyle_LIST`)

Заголовок — имя машины. Кнопки: `Выбрать` / `Назад` (-> «Мои машины»). Машину
идентифицирует ЗАХВАЧЕННЫЙ `carIndex` (индекс из списка «Мои машины»), НЕ
`listItem` под-диалога (это выбор ДЕЙСТВИЯ) — ре-валидируется против актуального
`owned()` на каждом клике; выбранный пункт сверяется с пересобранным набором
действий (паттерн `showCarActions` как раньше).

**Правило видимости**: ВСЕ пункты видны ВСЕГДА — недоступность объясняет
обработчик СООБЩЕНИЕМ при клике, не скрытием пункта. Динамический ЛЕЙБЛ 5-го
пункта (`Передать семье` / `Вернуть от семьи`) — это НЕ скрытие, это нормально.

1. **`Респавн`** — убрать/вернуть машину по текущему размещению:
   - **«вызвана»** (сессионная в мире, `vehicleId != -1`, НЕ припаркована) —
     занята водителем (`VehicleService::getDriver != -1`) -> отказ; текст зависит
     от того, КТО за рулём: сам нажавший — `Вы сами за рулём — выйдите из машины,
     чтобы её респавнить` (иначе отказ читался бы как баг «какой водитель, я
     один»), чужой водитель — `Пока в машине водитель, респавн недоступен`;
     иначе `VehicleService::destroy` — экземпляр уходит «в
     гараж» (владение НЕ удаляется, `subscribeDestroyed` обнулит `vehicleId`),
     игрок вызовет машину заново на центральной парковке. `Машина отправлена в
     гараж. Возьмите её на парковке`;
   - **«у дома» / «в семье»** (припаркована, `parked->vehicleId != -1`) — занята
     водителем (владелец ИЛИ член семьи) -> тот же развод текстов «сам за рулём /
     чужой водитель» (анти-гриф: не выдёргивать машину из-под члена семьи);
     иначе `ParkedVehicleService::
     respawnHome(dbId)` возвращает машину НА ЕЁ ТОЧКУ У ДОМА (spawn-позиция уже =
     точка парковки) через новый `VehicleService::respawn`. **КРИТИЧНО (анти-
     абьюз):** `respawn()` ядра сам даёт ПОЛНЫЙ БАК (`onVehicleRespawn`) —
     `respawnHome` СНАЧАЛА снимает ТЕКУЩИЙ остаток топлива в саму запись
     (`Parked::fuel`), а `ParkedVehicleSystem::onVehicleRespawned` (уже подписан
     на `VehicleService::subscribeRespawned`) восстанавливает его поверх дефолта
     — ТОТ ЖЕ путь, что уже закрывал «бесплатный эвакуатор с заправкой» после
     несанкционированной смерти, БЕЗ дублирования кода (см. `Docs/
     ParkedVehicles.md`, «Персист топлива»). `Машина возвращена на свою точку у
     дома`;
   - **«на парковке»** (записи парковки нет, владение `vehicleId == -1`) — отказ
     `Машина уже на парковке`;
   - **припаркована, но экземпляр временно отсутствует** (`parked->vehicleId ==
     -1`, напр. между внешним `destroy` и следующим `reconcile`) — `respawnHome`
     вернёт `NoInstance` -> `Машина сейчас недоступна`.
2. **`Показать на карте`** — без изменений (см. ниже).
3. **`Припарковать эту машину здесь`** — без изменений логики (см. ниже).
4. **`Убрать с парковки`** — без изменений логики (см. ниже).
5. **`Передать семье` / `Вернуть от семьи`** — динамический лейбл по
   `parkedMode(dbId)`:
   - **не расшарена** (`mode == NOT_PARKED` либо `NO_FAMILY`) -> лейбл `Передать семье` =
     прежняя `shareToFamily` (гейты/тексты БЕЗ изменений: нет семьи -> не владелец
     семьи -> не припаркована -> уже расшарена; уведомление членам семьи);
   - **расшарена** (`mode != NO_FAMILY`) -> лейбл `Вернуть от семьи`: гейт —
     владелец МАШИНЫ (машина всегда личная, шарится только своя припаркованная —
     владельцем СЕМЬИ быть не нужно, чтобы забрать свою же машину — тот же принцип,
     что у `/family` -> «Машины семьи» -> «Забрать»). `ParkedVehicleService::
     unshareFromFamily(dbId)` (метод существовал и раньше): `Ok` -> `Машина
     возвращена от семьи. Теперь ей пользуетесь только вы` + симметрично
     `shareToFamily` уведомление онлайн-членам семьи (`[{семья}] Семейная машина
     ({имя}) возвращена владельцу`, `{имя}` — `VehicleModelNames::displayName`);
     `NotShared`/`NotParked`/прочее -> `Сейчас нельзя вернуть машину, попробуйте
     позже`.

## Навигация

`под-диалог действий` -> `Мои машины` (Назад) -> `корень /car` (Назад); `Текущая
машина` -> `корень /car` (Назад). Правая кнопка корня — `Закрыть` (родителя нет).

## Действия без изменений (см. `Docs/ParkedVehicles.md` за деталями)

- **Показать на карте** — `liveVehicleId` резолвит live id (у припаркованной —
  через `ParkedVehicleService::byDbId`, у сессионной — из `owned`); `-1` ->
  `Эта машина на парковке. Возьмите её, чтобы отметить на карте`;
  иначе `VehicleWaypointService::showFor`.
- **Припарковать эту машину здесь** / **Убрать с парковки** — предусловия и
  ре-тег НА МЕСТЕ (без destroy/create) — идентичны прежней реализации, код не
  менялся при переработке меню.

## Правило видимости пунктов меню

Пункты диалог-меню (оба раздела) показываем ВСЕМ ВСЕГДА; недоступность (не в
машине / нет семьи / не владелец / не припаркована / занята водителем) —
сообщением при клике, не скрытием. Динамический ЛЕЙБЛ тумблера (завести/заглушить,
закрыть/открыть, передать/вернуть) — не скрытие, это нормально. Гейт — в
обработчике, не в `buildActions`.

## Регистрация команды

`PlayerCommandService::add("car", {}, …, perm = None, "меню личного транспорта:
текущая машина, парковка, семья, карта", HelpCategory::Misc)`. Без аргументов;
открыта всем; категория «Прочее» (`/help`). Корневой антифлуд команд — в
`PlayerCommandService`.

## Персист

`/car` ничего не хранит между сессиями. Владение — в БД на стороне
`PersonalVehicleService`; парковка — `ParkedVehicleService`; замок дверей —
СЕССИОННЫЙ, не персистится (`Docs/VehicleLock.md`). `VehicleWaypointService` — тоже
чисто сессионное состояние. **SQL-миграций нет.**

## Три правила

- **Читер-абуз:** `/car` работает ТОЛЬКО с серверными записями по `playerId`/
  `accountId` сессии; `carIndex` ре-валидируется против актуального `owned()` на
  КАЖДОМ шаге (список -> под-диалог -> действие); `listItem` под-диалога НЕ
  идентифицирует машину (только действие); «Текущая машина» проверяет владение
  СЕРВЕРНО (`ownCurrentVehicle`, ре-валидация на КАЖДОМ клике тумблера — диалог мог
  провисеть) — расшаренную семье машину чужого владельца нельзя ни закрыть/открыть,
  ни завести-от-чужого-имени (хотя сидеть в ней можно — доступ за руль решает
  отдельный `canDrive`). Замок и «Респавн» — см. `Docs/VehicleLock.md`/
  `Docs/ParkedVehicles.md` за деталями анти-абьюза (пер-игровой замок, снимок
  топлива перед `respawn`, гейт занятого водителем).
- **Краш/UB:** bounds `playerId` везде; null-гард `IPlayer`/`IVehicle` в колбэках;
  ре-валидация `carIndex`/`listItem`/`ownCurrentVehicle` на каждом клике;
  переоткрытие под-меню «Текущая машина» после действия не рекурсит бесконечно
  (обычный событийный колбэк диалога, не цикл); PER-TICK работы НЕТ.
- **Перф:** построение списков — холодный путь (по команде/клику), O(машин
  игрока); «Текущая машина» — O(1) (одна машина, один набор params); замок —
  см. `Docs/VehicleLock.md` (O(MAX_PLAYERS) только на флипе/share, не per-tick).

## Известные шероховатости опыта (геймдизайн, не баг движка)

- **Сессионность замка не объяснена игроку нигде в игре.** Замок сбрасывается в
  открытое состояние на каждой новой жизни экземпляра машины (в т.ч. после
  рестарта сервера) — `Docs/VehicleLock.md`, «Замок сессионный». Игрок узнаёт об
  этом только опытным путём (запер вчера — сегодня открыто), текст тумблера
  «Закрыть двери» не намекает на временность. См. предложение ниже.
