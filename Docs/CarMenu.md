# Меню личного транспорта (`/car`)

`/car` — бизнес-фича (НЕ Core): дистанционное меню личного транспорта игрока. Код:
`Src/Systems/CarMenuSystem`. Собственного сервиса нет — источник правды о владении —
`PersonalVehicleService`, о машинах — `VehicleService`, красный чекпоинт-указатель —
общий `VehicleWaypointService` (см. ниже). Дистанционный близнец пикапа парковки:
тот же список владения, тот же указатель, но вызывается откуда угодно по карте.

## Петля

1. `/car` — открывается **LIST-диалог** со списком ЛИЧНЫХ машин игрока (владение
   есть даже когда машина «в гараже»). Пустой список → в диалог НЕ заходим, сразу
   сообщение в чат.
2. Игрок **выбирает машину** — открывается **ПОД-ДИАЛОГ действий** по этой машине
   (`DialogStyle_LIST`): `Припарковать эту машину здесь` / `Убрать с парковки` /
   `Расшарить семье` / `Показать на карте`. Пункты видны ВСЕГДА (правило видимости).
3. Пункты **«Припарковать»/«Убрать с парковки»/«Расшарить семье»** управляют
   размещением машины у дома (см. `Docs/ParkedVehicles.md`): припарковать = гараж →
   лично у дома, убрать = у дома → гараж, расшарить = открыть доступ семье поверх
   припаркованной. Парковка/снятие — **ре-тег НА МЕСТЕ** (без destroy/create/респавна):
   машина не исчезает и не пересоздаётся, игрок остаётся в ней, меняется лишь режим.
   Все предусловия серверные, отказ объясняет обработчик сообщением.
4. Пункт **«Показать на карте»** — ставит персональный красный чекпоинт-указатель к
   машине (через общий `VehicleWaypointService`), если машина сейчас в мире.

## Правило видимости пунктов меню

Пункт под-диалога НЕ прячем по членству/роли/состоянию машины — показываем всегда;
недоступность объясняет обработчик СООБЩЕНИЕМ при выборе (видимый пункт учит, что
фича существует, и даёт путь к ней). Гейт держится в обработчике, не в `buildActions`.
Показ пункта прав НЕ даёт — обработчик авторитетно ре-валидирует всё на клике.

## Диалог списка (`DialogStyle_LIST`)

- Заголовок: `Личный транспорт` (тот же, что на пикапе парковки — единый словарь).
  Кнопки: слева `Выбрать`, справа `Закрыть` (корень — родителя нет).
- Строка пункта: `{n}. Модель {model}  —  {статус}`, `{n}` с 1, `{статус}` по
  `parkedMode(dbId)`: `у дома` (припаркована лично) / `в семье` (расшарена) / `в
  гараже` (`vehicleId == -1`, не припаркована) / `вызвана` (`vehicleId != -1`, в мире).
  Формат байт-в-байт с парковкой. Пример: `1. Модель 411  —  в гараже`.
- Имя машины SA не показываем (таблицы имён в гейммоде нет) — `Модель {id}`.
- Колбэк берёт **живого игрока** (`getPlayers().get(playerId)`) и **ре-получает**
  `owned()`; выбранный `listItem` валидируется по границам актуального списка
  (выбор ведёт в под-меню, а не спавнит).

## Под-диалог по машине (`DialogStyle_LIST`)

- Заголовок: `Модель {model}` (по какой машине действия). Кнопки: слева `Выбрать`,
  справа `Назад` (под-диалог — не корень; `Назад` переоткрывает список машин).
- Действия — вектор (`buildActions`): `Припарковать эту машину здесь` / `Убрать с
  парковки` / `Расшарить семье` / `Показать на карте` — все ВСЕГДА (не гейтим ВХОД по
  членству/роли/состоянию машины; недоступность объясняет обработчик сообщением).
- **Машину идентифицирует ЗАХВАЧЕННЫЙ `carIndex`** (индекс из списка), НЕ `listItem`
  под-диалога — `listItem` это выбор ДЕЙСТВИЯ.
- Колбэк: живой игрок; `response != Left` → `Назад` (переоткрыть список); иначе
  **ре-валидация `carIndex`** против актуального `owned()`, набор действий
  пересобирается и выбранный пункт сверяется с актуальным (набор изменился →
  перепоказать под-диалог).

## Действия размещения у дома (припарковать / убрать / расшарить)

Механика, предусловия и тексты — в `Docs/ParkedVehicles.md`. Кратко:

- **Припарковать эту машину здесь** (гараж → лично у дома): за рулём этой машины,
  ≤ `PARK_HOUSE_RADIUS = 30 м` от СВОЕГО дома (`houseOf` по серверному `accountId`),
  ещё не припаркована. Действие — **ре-тег НА МЕСТЕ** (тот же `vehicleId`, БЕЗ
  destroy/create): `setOwner(Parked)` + `setSpawnPosition(spot)` + `park(dbId, ...)`
  (INSERT в `parked_vehicle`, `family_id = NO_FAMILY`) + `detach(dbId)` из Personal.
  Игрок остаётся за рулём, HP/позиция сохраняются. Владелец онлайн — экземпляр остаётся в
  мире; на его ВЫХОДЕ `ParkedVehicleSystem::onOwnerOffline` личную ДЕСПАВНИТ (запись+БД
  целы), на следующем ВХОДЕ спавнит заново на точке — свежий экземпляр (это ОК, состояние
  сессионное). Расшаренная семье — исключение, живёт всегда.
- **Убрать с парковки** (у дома → гараж, НА МЕСТЕ): владелец машины, `isParked(dbId)`.
  Живой экземпляр из `byDbId(dbId)->vehicleId`. Действие (тот же `carId`, БЕЗ destroy):
  `setOwner(Player)` + `attach(dbId, carId)` в Personal + `unparkKeepInstance(dbId)`
  (DELETE, экземпляр не трогает). Машина остаётся стоять — снова личная сессионная.
- **Расшарить семье** (лично у дома → семейный доступ): владелец семьи (`isOwner`),
  машина припаркована ЛИЧНО (`parkedMode == NO_FAMILY`). Порядок отказов: **нет
  семьи** → **не владелец** → `dbId == -1` → не припаркована → уже расшарена. Действие:
  `shareToFamily(dbId, familyId)` = **только UPDATE `family_id`** (машину НЕ
  пересоздаём) + уведомление членам. Проверка членства ДО роли (даём путь `/family`).
  `shareToFamily`/`unshareFromFamily` внутри сервиса зовут `notifyReconcile(dbId)` →
  `ParkedVehicleSystem` приводит живой экземпляр к желаемому (личная→семья при
  владельце-оффлайн ЗАСПАВНИТ машину для семьи; семья→личная при оффлайне ДЕСПАВНИТ) —
  см. `Docs/ParkedVehicles.md`, «Жизненный цикл экземпляра». `CarMenuSystem` про
  `reconcile` НЕ знает (развязка через наблюдателя сервиса).

## Действие «Показать на карте»

`vehicleId = liveVehicleId(owned[carIndex].vehicleId, dbId)` — у припаркованной
владение detached (`vehicleId == -1`), живой экземпляр держит `ParkedVehicleService`,
поэтому id берём из `byDbId(dbId)->vehicleId` (иначе показали бы «в гараже», хотя
машина видна у дома); у обычной сессионной — из `owned`:

- `vehicleId == -1` (машина «в гараже», не в мире) → сообщение (см. таблицу): владение
  есть, но отмечать нечего;
- иначе `IVehicle* veh = VehicleService::get(vehicleId)`; `nullptr` (исчезла между
  открытием меню и выбором) → «недоступна»;
- иначе `VehicleWaypointService::showFor(player, *veh)` + успех.

Тот же `liveVehicleId(...)` разрешает live id и для статуса в списке `/car`
(`placementStatus`), чтобы «у дома»/«вызвана» считались верно у detached-парковки.

## Красный чекпоинт-указатель (общий `VehicleWaypointService`)

Указатель ведёт **общий `VehicleWaypointService`** (бизнес-фича вне Core,
`Src/Services/VehicleWaypointService`) — тот же слот переиспользует парковка (см.
`Docs/Parking.md`). Единый владелец «персональный чекпоинт к машине игрока»: один
слот на игрока (клиент показывает только один обычный чекпоинт), пере-вызов заменяет
прежний указатель.

- **`showFor(player, vehicle)`** — `CheckpointService::setForPlayer` на
  `vehicle.getPosition()` (серверная позиция), радиус `CHECKPOINT_RADIUS = 3.0`,
  `onEnter = clearFor`; запоминает целевой `vehicleId`. O(1).
- **`clearFor(player)`** — снять указатель (если стоит) + погасить клиентский
  чекпоинт. Идемпотентно. O(1).
- **`resetPlayer(playerId)`** — обнулить цель БЕЗ обращения к `CheckpointService` (на
  дисконнекте — клиентский чекпоинт сбросит сам `CheckpointService::resetPlayer`).
- **`findByVehicle(vehicleId)`** — id игрока с указателем на эту машину (или -1);
  `vehicleId == -1` → -1. Для снятия на уничтожении цели. O(MAX_PLAYERS), редко.

Привод — `VehicleWaypointSystem` (как `CheckpointSystem` для `CheckpointService`):
`bind` сервиса с `CheckpointService` в конструкторе; подписка на
`VehicleService::subscribeDestroyed` (машину-цель уничтожили → живой игрок `clearFor`
/ вышел `resetPlayer`); `onPlayerConnect`/`onPlayerDisconnect` → `resetPlayer`. Без
команд.

## Сообщения (через `u()`)

| Ситуация | Цвет | Текст |
|----------|------|-------|
| Нет транспорта (список пуст, диалог не открываем) | `ERROR_COLOUR` | `У вас нет личного транспорта. Купите машину и вызовите её на парковке` |
| Машина «в гараже» / не вызвана (`vehicleId == -1`) | `ERROR_COLOUR` | `Эта машина в гараже. Возьмите её на парковке, чтобы отметить на карте` |
| Машина недоступна (`get` → `nullptr`) / устаревший индекс | `ERROR_COLOUR` | `Эта машина больше недоступна` |
| Успех — отметил на карте (`showFor`) | `INFO_COLOUR` | `Ваша машина отмечена на карте красным чекпоинтом` |
| Припарковать — успех | `INFO_COLOUR` | `Машина припаркована у вашего дома. Она останется здесь и будет ждать вас` |
| Припарковать — нет дома | `ERROR_COLOUR` | `Чтобы парковать машину у дома, нужен свой дом. Займите свободный дом на карте` |
| Припарковать — не за рулём этой машины | `ERROR_COLOUR` | `Сядьте за руль этой машины, чтобы припарковать её` |
| Припарковать — далеко от дома | `ERROR_COLOUR` | `Пригоните машину к своему дому, чтобы припарковать её` |
| Припарковать — уже припаркована | `ERROR_COLOUR` | `Эта машина уже припаркована у дома` |
| Припарковать — `dbId` не присвоен | `ERROR_COLOUR` | `Машина ещё регистрируется, попробуйте позже` |
| Убрать с парковки — успех | `INFO_COLOUR` | `Машина снята с парковки` |
| Убрать с парковки — не припаркована | `ERROR_COLOUR` | `Эта машина не припаркована у дома` |
| Расшарить — успех | `INFO_COLOUR` | `Машина расшарена семье. Теперь ей могут пользоваться все члены семьи` |
| Расшарить — нет семьи (проверка ПЕРВОЙ) | `ERROR_COLOUR` | `У вас пока нет семьи. Создайте её через /family` |
| Расшарить — не владелец семьи | `ERROR_COLOUR` | `Расшарить машину семье может только владелец семьи` |
| Расшарить — не припаркована лично | `ERROR_COLOUR` | `Сначала припаркуйте машину у дома, потом откроете её семье` |
| Расшарить — уже расшарена | `ERROR_COLOUR` | `Эта машина уже расшарена семье` |
| Расшарить — `dbId` не присвоен | `ERROR_COLOUR` | `Машина ещё регистрируется, попробуйте позже` |
| Расшарить — гонка (машину убрали/расшарили) | `ERROR_COLOUR` | `Сейчас нельзя расшарить машину, попробуйте позже` |
| Уведомление членам семьи (при успехе) | `INFO_COLOUR` | `[{name}] Появилась новая семейная машина (модель {model})` |

`INFO_COLOUR {120,220,255}`, `ERROR_COLOUR {255,90,90}` — игровые цвета (как в
`ParkingSystem`/`FamilySystem`). Текст успеха **единый с парковкой** (не привязан к
«парковке» как к месту — машину отмечают откуда угодно).

## Регистрация команды

`PlayerCommandService::add("car", {}, …, perm = None, "меню личного транспорта:
припарковать у дома, расшарить семье, на карте", HelpCategory::Misc)`. Без аргументов; открыта всем;
категория «Прочее» (`/help`). Корневой антифлуд команд — в `PlayerCommandService`.

## Персист

`/car` ничего не хранит между сессиями. Владение — в БД на стороне
`PersonalVehicleService` (`personal_vehicle`), машина-сущность сессионная (подаётся
через парковку). `VehicleWaypointService` — чисто сессионное состояние (per-player
целевой `vehicleId`, `-1` = нет). **SQL-миграций нет.**

## Будущее

  остаётся **бесплатным и без кулдауна** — это навигация, а не экономика (иначе
  появится «налог на поиск своей машины»);
- справочник имён машин SA — заменит `Модель {id}` на имя (формат списка/заголовка
  не меняется).

## Три правила

- **Читер-абуз:** `/car` работает ТОЛЬКО с `owned` игрока (серверный список по
  `playerId`); индекс машины (`carIndex`) ре-валидируется против актуального `owned()`
  на КАЖДОМ шаге (список → под-диалог → действие); `listItem` под-диалога НЕ
  идентифицирует машину (только действие) — чужую машину указать нельзя; `showFor`
  раскрывает позицию только СВОЕЙ машины (`vehicleId` из своего `owned`, позицию
  берёт сервер `getPosition`); радиус чекпоинта фиксирован сервером; антифлуд команд
  — в `PlayerCommandService`.
- **Краш/UB:** bounds `playerId` во всех методах сервиса; null-гард `IPlayer`
  (`getPlayers().get` в колбэках после возможного дисконнекта) и `IVehicle`
  (`VehicleService::get`); ре-валидация `carIndex`/`listItem`; `showFor` null-гард
  `bind` (`m_checkpoints`); `findByVehicle` bounds-safe и не матчит пустые слоты
  (`vehicleId == -1`); снятие из `onEnter` безопасно (обработчик копируется до
  вызова); **ре-тег парковки/снятия:** тег/spawn меняем на ЖИВОМ валидном `veh`
  (в снятии перепроверен `get(carId)` — экземпляр мог пропасть внешним destroy → ветка
  `unparkKeepInstance` без разыменования); ре-тег синхронен в одном тике колбэка, без
  `destroy` → нет ре-энтрантного `onVehicleDestroyed`, правящего индексы; PER-TICK
  работы НЕТ.
- **Перф:** `showFor`/`clearFor` — O(1) без аллокаций; `findByVehicle` —
  O(MAX_PLAYERS) только на редком уничтожении машины; команда/диалоги — ХОЛОДНЫЙ путь
  (по вводу); построение тела списка — аллокация строки на холодном пути.
