# Корневой антифлуд команд

Код: `Src/Services/Core/PlayerCommandService` (логика), сброс на дисконнекте —
`Src/Systems/Core/PlayerCommandSystem`.

Единая точка защиты от спама командами. Через `PlayerCommandService::dispatch`
проходят ВСЕ команды чата, поэтому антифлуд живёт здесь — отдельным системам свой
кулдаун городить не нужно (и не нужно: кастомные кулдауны `/pay`, `/r` сняты).

## Где живёт

`PlayerCommandService::dispatch` — после того как команда найдена в реестре
(`it != m_commands.end()`) и ДО разбора аргументов/usage. Так ловится и спам
usage-сообщений (повтор команды с недостающими параметрами). Вся логика вынесена
в приватный `bool isFlooding(IPlayer&, StringView normalizedLine, TimePoint now)`,
`dispatch` остаётся читаемым.

Состояние — пер-игрок, `std::array<State, MAX_PLAYERS> m_state` в самом сервисе
(как `PlayerChatService`). На дисконнекте `PlayerCommandSystem::onPlayerDisconnect`
зовёт `PlayerCommandService::reset(id)` — иначе чужой блок/счётчик утёк бы в
переиспользованный слот.

## Правило сравнения «та же команда»

«Та же команда» = вся строка после `/` (имя + параметры) целиком,
регистронезависимо по ASCII (через `asciiLower`; кириллицу не трогаем). Пробелы
НЕ нормализуем. Строка нормализуется (ASCII-lower) в стековый буфер и сравнивается
с прошлой сохранённой. Обход сменой регистра (`/PAY` ↔ `/pay`) закрыт.

`lastCommand` хранится в фиксированном `std::array<char, 128>` + длина (без
аллокаций в горячем пути). Команды длиннее 128 байт сравниваются по префиксу —
для детекта одинакового спама этого достаточно.

## Алгоритм (в `isFlooding`)

1. `now = steady_clock::now()`. Если `now < blockUntil` — команда НЕ исполняется;
   если `now - lastNoticeAt >= CMD_FLOOD_NOTICE_COOLDOWN` — игроку уходит
   «Команды заблокированы. Осталось: N сек.» (N = ceil остатка `blockUntil - now`
   в секундах), `lastNoticeAt = now`; иначе молча. Возврат «флуд».
2. Иначе нормализованную строку сравниваем с `lastCommand`: совпала И
   `now - lastCommandAt < CMD_FLOOD_WINDOW` → `++repeatCount`; иначе
   `repeatCount = 1`.
3. `lastCommand = нормализованная`, `lastCommandAt = now`.
4. Если `repeatCount >= CMD_FLOOD_THRESHOLD` → `blockUntil = now + CMD_FLOOD_BLOCK`,
   `repeatCount = 0`, игроку «Слишком много одинаковых команд. Подождите 3 сек.»,
   `lastNoticeAt = now`, команда НЕ исполняется. Возврат «флуд».
5. Иначе — обычное исполнение (дальше по существующему коду `dispatch`).

## Константы (решение геймдизайнера)

Анонимный namespace в `PlayerCommandService.cpp`:

| Константа | Значение | Смысл |
|----|----|----|
| `CMD_FLOOD_THRESHOLD` | `5` | блок ставит 5-й одинаковый ввод подряд |
| `CMD_FLOOD_WINDOW` | `1500` мс | макс. интервал между повторами; больше — счётчик сбрасывается |
| `CMD_FLOOD_BLOCK` | `3000` мс | длительность блока ввода ВСЕХ команд |
| `CMD_FLOOD_NOTICE_COOLDOWN` | `1000` мс | мин. интервал показа сообщения о блоке |

## Область действия (что НЕ ловит)

Правило узкое по замыслу: блокирует только спам **идентичной** строкой (та же
команда + те же параметры) подряд. Сознательно НЕ покрывает:

- **варьируемый спам команд с побочным эффектом** — `/r` с разным текстом, `/pay`
  с разными суммами, `/me`/`/do`/`/try` с разным текстом: строки разные, счётчик
  не растёт. Темп таких команд ничем не троттлится (у них больше нет собственных
  кулдаунов). Дюпа/краша это не даёт — только флуд-аннойанс;
- **неизвестные команды** — проверка стоит после распознавания команды, поэтому
  спам `/zzz1`, `/zzz2`… не считается флудом (диспетчер отвечает «Неизвестная
  команда» без троттлинга).

Общий лимит темпа на игрока (токен-бакет) сюда сознательно не добавлен, чтобы не
бить по частым диалоговым командам; если варьируемый спам станет проблемой —
вводится отдельно.

## Тексты игроку

Цвет — `Colour::White()` (как прочие системные сообщения диспетчера), через
`Encoding::utf8Tocp1251`:

- при постановке блока: `Слишком много одинаковых команд. Подождите 3 сек.`
  (число = `CMD_FLOOD_BLOCK` в секундах);
- при попытке выполнить команду во время блока: `Команды заблокированы. Осталось:
  N сек.` (N = ceil остатка блока в секундах).

## Три правила

- **Читер-абуз:** сравнение по серверно-хранимой прошлой строке (клиенту не
  верим); блок — серверный; обход сменой регистра закрыт (ASCII-регистронезависимо).
  Антифлуд НЕ заменяет модерацию: мут `/me`/`/do`/`/try` остаётся в
  `RoleplayChatSystem` через `PlayerChatService::isMuted` (заглушённый игрок не
  эмоутит).
- **Краш:** индексация по `player.getID()` (валиден для `IPlayer&`), с
  bounds-guard `0..MAX_PLAYERS`; стековый буфер не переполняется (длина клампится
  к `LAST_COMMAND_CAP`); путь синхронный (на главном потоке), без async-гонок и
  реэнтрантности; `reset(id)` на дисконнекте — против утечки состояния в слот.
- **Перф:** `dispatch` — событийный путь (на команду), не per-tick. Флуд-проверка
  O(длины строки) (нормализация + сравнение), без аллокаций (фиксированный буфер).
