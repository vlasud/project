# Фракции

Базовая система организаций. Код: `Src/Services/FactionService`, `Src/Systems/FactionSystem`.
Схема БД: `Sql/factions.sql` (`faction_rank`, `faction_member` — c колонкой
`skin` выбранного скина организации, `faction_budget`).

## Устройство

- **Фракции — часть кода**: регистрируются `registerFaction(id, имя, [куратор, бит])`,
  новую без кода не добавить. В БД только данные: ранги, члены, бюджеты.
- **Лидер** — флаг члена. Назначается: для администрации (id 1) — итогом выборов,
  для подопечных фракций — куратором через `/gov`, вручную — дев-меню `/fdev`.
- **Ранг** = название + маска доступа. Никаких числовых лестниц.
- **«Без ранга»** — стартовый ранг, есть у каждой фракции автоматически
  (создаётся при загрузке, если нет). Удалить нельзя. На него попадают новички
  и обладатели удалённых рангов.
- **Зарплата** — персональная у каждого члена (не у ранга). Прописывается при
  найме, меняется `/setsalary`.
- **Бюджет** — счёт организации («деньги в банке»). Из него платятся зарплаты.
  Пока пополняется только дев-меню; доходные механики — будущее.
- **База** — здание организации: интерьер, пикап входа на улице, пикап выхода
  внутри и две точки телепорта. Вход — только членам фракции. Внутри изоляция
  по виртуальному миру (= id фракции): базы разных организаций могут делить
  один интерьер, не видя друг друга. Базу регистрирует система конкретной
  фракции (`registerBase`), пикапы и телепорт — common-привод.
- **Точка спавна** — члены организации появляются на ней при каждом спавне
  (`registerSpawn`; у АП — внутри базы). Вступление/выход/появление в сети
  переключают точку немедленно; вне фракции — гражданский дефолт.
- **Цвет** — уникальный у каждой организации (`registerColour`): ник и маркер
  на миникарте члена красятся в него; вне фракции — гражданский серый.
- **Скин организации** — член ВСЕГДА в скине своей организации, пока состоит.
  При найме (вступлении в фракцию) обязательно надевается ПЕРВЫЙ скин из пула;
  при увольнении возвращается ЛИЧНЫЙ (гражданский) скин аккаунта — персистентный,
  см. `PlayerPersonalSkinService` (`player.skin` в БД, дефолт по полу муж 78 /
  жен 77). Пока игрок состоит во фракции, его личный скин в источнике правды
  остаётся неизменным (отображается органный), а на конце сессии в БД пишется
  именно личный, а не органный. Выбранный членом скин организации хранится
  в БД (`faction_member.skin`, 0 = не задан → первый из пула) и берётся оттуда
  на следующем заходе. Если у организации пул пуст (напр. банки) — надевать
  нечего, скин не трогается. Невалидный/исчезнувший из пула сохранённый скин →
  фолбэк на первый из пула. Применение — единая точка `applyFactionSkin` на
  событии членства (вход/появление в сети → скин организации; выход → возврат
  личного).

### Модель применяемого скина: БАЗА + временный

`PlayerSkinService` (Core) разделяет применяемый скин на **базу** и **временный
оверрайд**. К клиенту показывается `temp` (если активен), иначе `база`.

- **База** (`setSkin`/`getSkin`) — орг-скин (если в организации) ИЛИ личный
  (если нет). Именно базу читает `PlayerSpawnService` для спавн-инфо, поэтому на
  СПАВНЕ игрок всегда появляется в базе: член — в орг-скине, остальные — в личном.
  `applyFactionSkin` ставит базу на смене членства; auth ставит личный как базу
  на логине (до старта членства).
- **Временный** (`setTempSkin`/`clearTempSkin`) — оверрайд поверх базы,
  показывается немедленно и живёт ДО ближайшего респауна. На спавне снимается
  (`PlayerSkinSystem::onPlayerSpawn` → `clearTempSkin`), спавн-инфо его не
  содержит — поэтому переспавн возвращает базу.

Команды (админские, см. `Docs/Admin.md`):
- **`/devskin [id] [skin]`** меняет ТОЛЬКО личный скин аккаунта (источник правды
  `PlayerPersonalSkinService`, write-through в `player.skin`). Визуально новый
  личный скин применяется СРАЗУ, только если цель НЕ во фракции И нет активного
  временного скина; член организации остаётся в орг-скине (личный увидит лишь при
  увольнении), а при активном `/askin` личный покажется после респауна.
- **`/askin [id] [skin]`** — временный скин: показывается мгновенно, живёт до
  ближайшего респауна, в БД и в личный/орг-скин не пишется.
- **Пул скинов** (`registerSkins`) — члены с правом «Смена скина» выбирают из
  него через `/skin`; выбор пишется в БД (write-through) и применяется сразу.
  Вся полиция — общий пул POLICE_SKINS (Systems/Factions/PoliceSkins.h):
  265-267, 280-285, 288, 300-303. АП: 9, 17, 57, 59, 76, 91, 141, 147, 148,
  163-166, 185-187, 227, 228, 295. ФБР: 286 (агент FBI), 166, 165, 164, 163,
  150, 141, 17. Триада: 49, 55, 117, 118, 120-123, 186, 193, 208, 224, 263, 294.
  Rifa: 44, 56, 173-175, 184, 226, 242, 273. Grove Street: 105-107.
  Ballas: 102-104. Vagos: 108-110. Aztecas: 114-116.
  Русская мафия: 111, 112, 120-125. Итальянская мафия: 111-116.
  Банк: 147, 148, 163-166 (деловые скины).
  Армия СВ: 287 (единственный военный пед в SA). Армия ВВС: 287 (отдельного
  скина ВВС в каноне SA нет — тот же военный пед; пул легко расширить позже).
- **Рация `/r [текст]`** — сообщение всем членам организации онлайн, формат
  `[R] [Ранг] Ник[id] : текст`, весь текст светло-зелёный. Своего кулдауна нет —
  спам отсекает корневой антифлуд команд (`PlayerCommandService`, см.
  `Docs/CommandFlood.md`). Мут на рацию не распространяется (вне задачи).

## Маска доступа ранга

Базовые биты (есть у каждой организации):

| Бит | Право | Что открывает |
|----|----|----|
| 0 | Приглашение игроков | `/invite`, `/setsalary` |
| 1 | Увольнение игроков | `/uninvite` (лидера и себя — нельзя) |
| 2 | Доступ к бюджету | зарезервировано (операции с бюджетом) |
| 3 | Смена скина | `/skin` — выбор из пула скинов организации |

С бита 8 — биты конкретных организаций (`registerPermission`); появятся
вместе с конкретными фракциями (полиция: розыск, склад и т.п.).

У лидера все биты всегда. Тогглы прав — в меню ранга (`/faction` → ранги).

## Гос-вертикаль

Администрация Президента (id 1) курирует: полиции ЛС/СФ/ЛВ (2–4), городские
банки СФ/ЛВ (6–7), ФБР (8), армию СВ/ВВС (15–16). Президент = лидер
администрации (избирается, см. Elections.md), управляет всеми подопечными
всегда. Банк (5) — самостоятельная организация, кураторством АП не охвачена.

Право управления ПЕРЕДАЁТСЯ ПО-ОРГАНИЗАЦИОННО: у ранга куратора есть список
«Подопечные организации» (меню ранга) — президент создаёт ранг «Министр ВД» и
отмечает ему полиции трёх городов; ранг «Министр финансов» получает банки.
Обладатель ранга видит в `/gov` только переданные ему организации. По каждой
он может: назначить лидера, снять лидера (снятие оставляет человека в штате на
его ранге) и УВОЛИТЬ любого сотрудника — полное исключение из организации,
включая лидера (куратор выше внутрифракционного запрета `/uninvite`, где лидера
трогать нельзя). Выбор сотрудника — из списка онлайн, без ручного ввода id.
Серверная админка в цепочке не участвует (только бутстрап через `/fdev`).

Инвариант: передавать организации рангам может ТОЛЬКО лидер куратора
(президент) — правка скоупов живёт в меню рангов, доступном лишь лидеру, а
сервис дополнительно отказывает в передаче организации, которую фракция
редактора не курирует. Лидер подразделения (полиции) кураторством не
распоряжается ни в какой форме.

## Выплата зарплат (ручной цикл)

1. Лидер: `/faction` → «Приказ о выплате зарплат» (видит бюджет, подтверждает).
2. Сумма всех персональных зарплат (включая оффлайн-членов) списывается с
   бюджета. Не хватает на всех — приказ не проходит целиком.
3. Каждому члену зачисляется чек на его зарплату на счёт в банке (копится,
   см. Bank.md). Онлайн-члены получают уведомление.
4. Кулдаун приказа помечается только после успешного списания.

## Команды

Основной путь лидера — одно меню `/faction` (команды ниже остаются шорткатами):
- **Сотрудники** — список членов онлайн → карточка (ранг/зарплата/увольнение)
  без ручного ввода id; отсюда же «Нанять сотрудника» (id → выбор ранга →
  зарплата одной цепочкой).
- **Мой ранг** — назначить себе ранг из списка.
- **Управление рангами** — создание ранга идёт через пресеты прав (Рядовой /
  Офицер / Заместитель / Настроить вручную), дальше тогглы.
- **Приказ о выплате зарплат**, **Информация о фракции**.

| Команда | Кто | Что |
|----|----|----|
| `/faction` | член | инфо; лидеру — меню организации (сотрудники, ранги, приказ, мой ранг) |
| `/invite [id]` | бит 0 | найм (шорткат к цепочке id→ранг→зарплата) |
| `/uninvite [id]` | бит 1 | увольнение |
| `/setrank [id]` | лидер | назначение ранга (диалог) |
| `/setsalary [id]` | бит 0 | изменение зарплаты |
| `/skin` | бит 3 | смена скина из пула организации (выбор сохраняется в БД) |
| `/r [текст]` | член | рация организации |
| `/gov` | скоуп ранга | назначить/снять лидера, уволить любого сотрудника подопечной |
| `/fdev` | дев (до ролей) | список, принять/лидер/исключить, бюджет |

## Правила-инварианты

- Лидер у фракции один: назначение нового снимает прежнего (везде, включая БД).
- «Без ранга» удалить нельзя (фракция без рангов невозможна); обладатели
  удалённого ранга переводятся на «Без ранга».
- Членство одно: вступление в фракцию возможно только из «без фракции»
  (исключение — назначение лидером по итогам выборов переводит принудительно).
- Лидера нельзя уволить из фракции (только снять через куратора/админку).
- Член всегда в скине организации, пока состоит: при найме — первый из пула,
  при увольнении — прежний гражданский (или дефолт по полу: муж 78 / жен 77). Выбор скина персистится
  в `faction_member.skin`; невалидный/не из пула → первый из пула. Пустой пул
  (банки) — скин не применяется.
