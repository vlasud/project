# GPS-навигация `/gps` и телепорт `/tp`

Навигация к именованным местам мира. Бизнес-фича (НЕ Core), кроме лока навигации
(он Core-инфраструктура). Код: `Src/Systems/GpsSystem`,
`Src/Services/Core/NavigationLockService` (лок), плюс расширение
`Src/Services/VehicleWaypointService` (GPS-режим единого чекпоинт-слота).

- **`/gps`** (всем) — диалог-каталог мест + пункт «Отключить GPS». Выбор места
  ставит красный чекпоинт-указатель до точки; вход в чекпоинт гасит маркер и шлёт
  сообщение о прибытии. Новый выбор заменяет старый.
- **`/tp`** (админ уровня 1+) — тот же каталог, но выбор СЕРВЕРНО телепортирует
  админа (`PlayerLocationService`, grace анти-чита).

## Каталог мест (общий для `/gps` и `/tp`)

Единая таблица `m_places` в конструкторе `GpsSystem` (легко правится/расширяется —
геймдизайнер финалит список на ревью). Пункты показываются ВСЕМ ВСЕГДА; недоступность
(нет дома / не член орга) объясняет сообщение при клике, не скрытие (конвенция UI).

Порядок = порядок строк диалога (`listItem` 0-based). Статические координаты взяты
из реального мирового контента:

| 1 | Автобусное депо — работа водителем | Static | `{1204.0439, -1823.2920, 13.5918}` (пикап BusJobSystem) |

Статические строки 0–7 приходят из общего каталога `PlaceCatalogService` (его же читает
выбор точки назначения в такси, см. `Docs/TaxiJob.md`); «Мой дом» и «Моя организация»
дописывает хвостом сама `GpsSystem` — каталог про дома и фракции не знает.

Статические места — интерьер 0, мир 0. Динамические резолвятся от ИГРОКА в момент
клика (для `/tp` — от админа: его дом / его база), образец `SpawnChoiceSystem`.
Общий резолвер `resolvePlace(player, index, navigation, out)`: `false` + сообщение,
если место недоступно («У вас нет своего дома. Займите свободный дом на карте», «Вы
не состоите в организации», «Авторизуйтесь…»). И `/gps`, и `/tp` используют один
резолвер (не копипаст); флаг `navigation` разводит цель «Моей организации».

**«Моя организация» — цель зависит от назначения (`navigation`).** Spawn большинства
фракций стоит ВНУТРИ интерьера в приватном мире (`virtualWorld` = id фракции,
`interior` != 0). Обычный чекпоинт умеет только XYZ мира 0, поэтому:

- `/gps` (`navigation=true`) ведёт на **уличный вход базы** —
  `faction->base.entrances.front().pickupPos` (мир 0, интерьер 0): достижимая точка,
  `onEnter` сработает. Иначе GPS-цель повисла бы на ~1000 м в мире 0 и маркер не гас
  бы никогда. Орг без интерьер-базы (Army — spawn на улице, `base.defined=false` /
  пустые `entrances`) — фолбэк на `spawn` и для навигации.
- `/tp` (`navigation=false`) телепортирует на сам `spawn.position` с его
  `interior`/`virtualWorld` — телепорт переносит интерьер/мир разом (внутрь базы).

## `/gps` (все игроки)

Команда `gps` — без гейта прав (`PermissionSpec` = None). В `/help`, секция «Прочее»
(`HelpCategory::Misc`), описание «проложить маршрут к нужному месту» — универсальный
навигатор качества жизни, нужен новичку. Диалог `LIST` «GPS-навигация»: строки
каталога + последней строкой `{FFB400}Отключить GPS` (амбер выделяет управляющее
действие среди белых имён мест; цвет-код не сдвигает индекс = размеру каталога).

- **Выбор места** (`listItem` в `[0, N)`): сначала проверка лока навигации (см.
  ниже) — при удержании отказ с причиной, БЕЗ маркера. Иначе `resolvePlace`; при
  доступности — `VehicleWaypointService::showGpsFor(player, position, onArrive)`:
  красный персональный чекпоинт (радиус 3.0). Сообщение «GPS: маршрут до «…»
  построен». Вход в чекпоинт → маркер гаснет (`clearFor` внутри `onEnter`) +
  «Вы прибыли: …. GPS отключён».
- **«Отключить GPS»** (`listItem == N`): если стоит именно GPS-маркер
  (`hasGpsWaypoint`) — гасим (`clearFor`) + «GPS отключён»; иначе мягкое «Активного
  GPS-маршрута нет» (парковочный/домашний указатель этот пункт НЕ трогает).

**Единый чекпоинт-слот.** Клиент показывает только один обычный чекпоинт, поэтому
GPS-маркер идёт через `VehicleWaypointService` — ЕДИНОГО владельца этого слота
(парковка, `/car`, `/home`, «отметить на GPS» в `/auc` тоже там). Семантика «последний выигрывает»: новый
GPS-выбор заменяет прежний GPS-маркер И любой парковочный указатель, и наоборот. НЕ
заводим второго владельца слота через прямой `CheckpointService` — иначе два хозяина
гасили бы чекпоинты друг друга (а авто-съём `findByVehicle` на уничтожении машины
снял бы GPS). GPS-цель помечена `gps=true` (vehicleId=-1 — `findByVehicle` её не
матчит) — так `hasGpsWaypoint`/`clearGpsFor` отличают её от парковки/дома.

Маркер СЕССИОННЫЙ: на дисконнекте гаснет вместе со слотом (`VehicleWaypointSystem`
сбрасывает `VehicleWaypointService`). С race-слотом маршрута автобуса не
конфликтует (разные клиентские слоты) — да и лок всё равно закроет GPS в смене.

### Решение по консистентности лока в `/gps`

При удержанного лока навигации диалог `/gps` ВСЁ РАВНО открывается (пункты видны
всегда — общая конвенция UI), а отказ выдаётся при ВЫБОРЕ места: «GPS недоступен:
{причина}». Проверка на клике (серверный факт `NavigationLockService::isLocked`), не
на открытии — лок мог смениться, пока диалог висел. «Отключить GPS» под локом даёт
мягкое «нет маршрута» (маркер уже погашен взятием лока).

## `/tp` (админы уровня 1+)

Команда `tp` — гейт `PermissionSpec::admin(1)` (ЭФФЕКТИВНЫЙ уровень после `/alogin`,
как прочие админ-команды; резолвер общий — `PlayerCommandSystem`). `HelpCategory::
Hidden`; в `/ahelp` попадает автоматически, как все админ-команды. Диалог `LIST`
«Телепорт» — тот же каталог (переиспользуем `buildPlacesBody`, без «Отключить GPS»).

Выбор места → СЕРВЕРНЫЙ телепорт `PlayerLocationService::teleport(player, position,
interior, virtualWorld)` (grace анти-чита, переносит интерьер/мир разом — НЕ сырой
`setPosition`, иначе валидатор словил бы «телепорт-хак»). Сообщение «Вы
телепортированы: …». Динамические места резолвятся ОТ АДМИНА (его дом / его база).

**`/tp` живёт в `GpsSystem` (не в `AdminSystem`).** Каталог и резолвер мест — в
`GpsSystem`; `/tp` — тонкая админ-гейтед команда над тем же каталогом. В `AdminSystem`
пришлось бы публично выставлять каталог/резолвер или копипастить — избегаем.

### Админ за рулём

`/tp` требует, чтобы админ был НА НОГАХ. За рулём/пассажиром — отказ «Выйдите из
транспорта, чтобы телепортироваться»; мёртв/спектатор — «Сейчас нельзя
телепортироваться». Причина: `PlayerLocationService` — авторитетный источник о
позиции ИГРОКА и двигает только его; телепорт водителя оставил бы машину позади
(десинк / «призрак»), а корректного примитива «телепорт машины с водителем под
grace» в `VehicleService` нет. Отказ — чистый и безопасный выбор (TZ допускает).
Стейт — серверный (`PlayerStateService`), клиенту не верим.

Лок навигации на `/tp` НЕ распространяется (телепорт чекпоинт-слот не трогает). Если
админ телепортнётся посреди своей смены автобусника — просто словит штатное
увольнение за простой/невозврат за руль; отдельной обработки не нужно.

## Лок навигации (`NavigationLockService`, Core)

Генеричный лок: пока держится — `/gps` отказывает выбором места. Бизнеса внутри нет,
причина — просто строка (utf-8) от держателя. ОДИН держатель на игрока: сервис сам
вложенности не считает (повторный `acquire` ПЕРЕЗАПИСЫВАЕТ причину, `release`/`reset` —
идемпотентны). Непересечение смен обеспечивают САМИ работы: `onStartWork` обеих работ
отказывает устройству, если лок уже удержан (см. «Взаимное исключение работ» ниже),
поэтому в один момент лок держит ровно одна смена.

- `acquire(playerId, reason)` — взять лок + оповестить `subscribeAcquired`.
- `release(playerId)` — снять.
- `isLocked` / `lockReason(playerId)` — чтение (для отказа `/gps`).
- `reset(playerId)` — сброс на дисконнекте.
- `subscribeAcquired(cb)` — оповещение о ВЗЯТИИ (для гашения GPS).

**Взятие лока гасит активный GPS-маркер.** Сам сервис клиентский чекпоинт не трогает
(слот принадлежит бизнес-слою): `acquire` оповещает `subscribeAcquired`, а гасит
GPS подписчик — `GpsSystem` зовёт `VehicleWaypointService::clearGpsFor` (только
GPS-цель, парковочный/домашний указатель не трогает). Так к моменту, когда работа
займёт чекпоинт-слот своими маркерами, GPS уже снят, а книга `VehicleWaypointService`
чиста.

**Сброс на дисконнекте.** `GpsSystem` на `PlayerSessionService::subscribeEnd` зовёт
`reset(playerId)` — переиспользуемый слот не наследует чужой лок. Это страховка:
работы освобождают лок сами на конце смены (ниже).

### Держатели лока и ВСЕ пути release

**BusJobSystem — лок на ВСЮ смену** («идёт смена водителя автобуса»):
- `acquire` — в `onStartWork` сразу после `startWork` (успех = Reserved ИЛИ Queued;
  лок держится и в очереди — очередь это та же смена). Провал посадки
  (`failBoarding` → `requeueTail`) возвращает в очередь — НЕ конец смены, лок держим.
- `release` — на КАЖДОМ конце смены:
  1. `teardownShift` — общий teardown: покрывает `dismiss` (добровольное «Завершить
     работу» из Reserved/Driving, смерть `onPlayerDeath`, тайм-ауты
     посадки/возврата/анти-AFK в `tickWorker`) И `onSessionEnd` (дисконнект в любой
     фазе);
  2. `onFinishWork` ветка Queued — выход из очереди (идёт `endShift` напрямую, минуя
     `teardownShift`);
  3. `pumpQueue` — продвинутый работник, ПРОПАВШИЙ из пула (дисконнект) — на всякий
     (почти недостижимо; дисконнект уже прошёл `onSessionEnd`).

**PortJobSystem — лок на ВСЮ смену грузчика** («идёт смена грузчика в порту»):
- `acquire` — в `onStartWork` сразу после успешного `startWork`.
- `release`:
  1. `onFinishWork` — после `endWork` (штатное завершение смены);
  2. `resetPlayer` — конец сессии/дисконнект в любой фазе (общий teardown порта).
- Смерть (`onPlayerDeath`) смену НЕ завершает (delivered жив, чекпоинт источника
  возвращает `onPlayerSpawn`) — лок НЕ снимаем.

### Взаимное исключение работ

Обе работы делят один чекпоинт-слот и один лок навигации. Порт не имеет таймаута/
привязки к позиции в фазе `GoToSource`, поэтому игрок мог бы, начав смену порта, дойти
до депо и устроиться водителем — вторая работа перезаписала бы лок и персональный
чекпоинт первой, а её `release` затем разблокировал бы `/gps` при ещё активной чужой
смене. Чтобы этого не было, `onStartWork` ОБЕИХ работ, ПОСЛЕ отсева «уже в этой работе»
и ДО списаний/старта смены, отказывает при `m_navLockService.isLocked` («Нельзя
устроиться …: {причина текущей смены}»). Так занятой игрок не может стартовать вторую
работу — смены не пересекаются, слоты одной работы под ней и остаются.

## Порядок регистрации

- `ServiceRegister.cpp`: `NavigationLockService` (без зависимостей) — после
  `VehicleWaypointService`.
- `SystemRegister.cpp`: `GpsSystem` после `VehicleWaypointSystem` (слот GPS связан с
  `CheckpointService`), `Bus/PortJobSystem` (держат лок; подписка на `subscribeAcquired`
  в конструкторе успевает до первого устройства на работу в игре), `HouseSystem`/
  `FactionSystem` (динамические места). Команды регистрируются в конструкторе;
  диалог/чекпоинт/телепорт — холодный путь.

## БД

Не меняется — фича полностью в памяти (маркер/лок сессионные, каталог — константы,
динамические места читают уже существующие `HouseService`/`FactionService`).

## Три правила

- **Читер-абуз:** `/gps` открыт всем, но выбор мест валидируется серверно — «Мой
  дом» требует ВЛАДЕНИЯ (`houseOf` по серверному `accountId` из сессии), «Моя
  организация» — членства + `spawn.defined` (в чужой дом/базу не навести/не
  телепортнуться); GPS-цель орга — уличный вход базы (мир 0), достижимый чекпоинтом.
  `/tp`
  — гейт по ЭФФЕКТИВНОМУ админ-уровню (общий резолвер, после `/alogin`); телепорт
  только СЕБЯ, к фиксированным/своим точкам, через `PlayerLocationService` (grace, не
  сырой setPosition). Диспетч по индексу строки диалога, не по клиентскому тексту.
  Стейт «за рулём» для `/tp` — серверный (`PlayerStateService`). Лок навигации
  читается из серверного факта (`isLocked`), проверка на клике.
- **Краш/UB:** во всех колбэках диалога — `getPlayers().get()` + null-гард; резолв
  мест null-гардит `session`/`NO_ACCOUNT`, `houseOf` (nullptr), `getFaction`
  (nullptr). `subscribeAcquired`-колбэк резолвит игрока по id + null-гард. Bounds-гард
  `playerId` во всех методах `NavigationLockService`/`VehicleWaypointService`. GPS
  onEnter снимает маркер безопасно (CheckpointService копирует обработчик до вызова —
  нет ре-энтрантной порчи слота). Нет таймеров/самоотмены. Индекс места bounds-check
  перед доступом к `m_places`.
- **Перф:** всё — ХОЛОДНЫЙ путь (команда → диалог по запросу). Ни `/gps`, ни `/tp`,
  ни лок не имеют per-tick работы. `acquire`/`release`/`isLocked` — O(1).
  `buildPlacesBody`/`resolvePlace` — O(числа мест) + одна аллокация тела диалога, по
  клику. `hasGpsWaypoint`/`clearGpsFor` — O(1). `subscribeAcquired`-оповещение — по
  одному разу на устройство на работу (не per-tick).
