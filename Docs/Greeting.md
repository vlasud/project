# Приветствие при входе на сервер (GreetingSystem)

Бизнес-фича (не Core): при успешном входе игрока на сервер показывается
попап-приветствие с его ником на едином экранном textdraw через
`ScreenNoticeService` (см. `Docs/ScreenNotice.md`).

Код: `Src/Systems/GreetingSystem/GreetingSystem.{h,cpp}`. Зависимости из
регистра сервисов: `ScreenNoticeService` (показ), `PlayerSessionService`
(момент старта сессии). Регистрация — `Src/Systems/SystemRegister.cpp`, сразу
после `PlayerSessionSystem` (подписка на `subscribeStart` — сессия уже активна,
ник опознан).

## Механика

- **Триггер** — `PlayerSessionService::subscribeStart`: сессия стартует после
  успешного логина/регистрации (`PlayerAuthSystem`), то есть игрок уже
  аутентифицирован. На гостевое/неудачное подключение попап не показывается.
- **Текст** — `"Добро пожаловать, " + player.getName()`. Ник берётся из
  `IPlayer::getName()` — строго латиница `Имя_Фамилия`, валидирован
  `NicknameService` до входа (см. `Docs/Nickname.md`, если есть) — безопасен
  для textdraw без дополнительной санитизации сверх той, что уже делает
  `TextDrawService`.
- **Показ** — `ScreenNoticeService::show(player, text, GREETING_TIME,
  Colour::White())`. Если в этот момент на экране игрока уже что-то показано
  (маловероятно сразу на входе, но структурно возможно), попап встаёт в общую
  pending-очередь `ScreenNoticeService` наравне с любым другим консюмером —
  никакого приоритета у приветствия нет.

## Константы баланса

| Константа       | Значение | Смысл                                  |
|-------------------|----------|-----------------------------------------|
| `GREETING_TIME`   | `5000 ms`| длительность попапа-приветствия          |
| Цвет              | белый (`Colour::White()`) | дефолт; может быть скорректирован геймдизайнером |
| Текст             | `"Добро пожаловать, <ник>"` | финальную формулировку может скорректировать геймдизайнер |

## Три правила

- **Читер-абуз.** Чистая косметика — сообщение сервер -> клиент, никакой
  игровой логики не завязано. Текст строится из серверного факта (`getName()`
  уже валидированного аккаунта), клиентский ввод в текст не попадает. Показ —
  один раз на старт сессии (не per-tick, не по клиентскому запросу) — спам-
  вектора нет.
- **Краш-безопасность.** `subscribeStart` вызывается с гарантированно живым
  `IPlayer&` (см. `PlayerSessionService`). `ScreenNoticeService::show` сам
  делает bounds-чек `playerId` и гард на неинициализированные зависимости —
  падений при отсутствии компонента textdraw/timer нет (попап тихо не
  показывается).
- **Перф.** Событийно — один вызов на подключение/логин игрока, не per-tick.
  `show()` — O(1) (см. `Docs/ScreenNotice.md`), единственная аллокация —
  конкатенация строки приветствия (одна на игрока на сессию).
