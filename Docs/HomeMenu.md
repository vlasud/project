# Меню дома (`/home`)

`/home` — бизнес-фича (НЕ Core), меню владельца дома. Код: `Src/Systems/HomeMenuSystem`.
Собственного сервиса нет — источник владения/контента дома `HouseService`,
парковка у дома `ParkedVehicleService`, красный чекпоинт-указатель — общий
`VehicleWaypointService`. Персист владения (передача/выселение) идёт ЧЕРЕЗ
`HouseService::setOwner` + подписку `HouseSystem::onOwnerChanged` — сама
`HomeMenuSystem` в БД НЕ пишет (см. `Docs/Houses.md`, «Передача и выселение»).

## Гейт входа

У игрока есть СВОЙ дом — `HouseService::houseOf(std::to_string(accountId))` по
серверному `accountId` из `PlayerSessionService`. Нет дома или нет активной
сессии → `У вас нет своего дома. Займите свободный дом на карте` (`ERROR_COLOUR`,
дословно как отказы гейта дома в семье/`/setspawn` — одна причина, одно слово;
формулировка согласована с отказом `parkHere` в `Docs/CarMenu.md`), меню НЕ
открывается.

## Корень `Мой дом — {тип интерьера}`

**LIST-диалог**, заголовок — тип интерьера дома (каталог `HouseService::catalog()`).
Кнопки `Выбрать` / `Закрыть` (родителя нет). 6 пунктов, **ВСЕ ВИДНЫ ВСЕГДА**
(правило видимости — не прячем по состоянию/капу/чему-либо; недоступность
объясняет сам обработчик сообщением при клике, гейт не в построении списка):

1. Информация
2. Отметить на карте
3. Улучшения
4. Передать владение
5. Продать
6. Выселиться

Ре-валидация `houseOf` на КАЖДОМ клике каждого пункта — диалог мог висеть, пока
дом передавался/продавался/выселялся из другого окна (или той же сессией в
параллельном диалоге). Потеря дома между показом корня и кликом → `У вас больше
нет дома` (`ERROR_COLOUR`), пункт не выполняется.

## 1. Информация

**TABLIST_HEADERS** «Поле | Значение» (образец — `MenuSystem::showInfo`, карточка
без интерактивных строк). Кнопки `Назад` / `` (пусто — просмотр, вторая кнопка
не нужна). Текущие поля (раздел заведомо РАСШИРЯЕМЫЙ — новые факты о доме
добавляются новыми строками без переделки структуры):

| Поле                    | Значение                                                      |
|--------------------------|----------------------------------------------------------------|
| Тип дома                 | `catalog()[interiorIndex].name`                                 |
| Лимит машин у дома       | `House.parkingCap`                                              |
| Припарковано сейчас      | `ParkedVehicleService::countParkedByAccount(accountId)`          |

`Назад` → корень `/home`.

## 2. Отметить на карте

Персональный красный чекпоинт на ВХОДЕ дома (`house->entrance`), через
`VehicleWaypointService::showFor(IPlayer&, const Vector3&)` — **target-режим
«точка»** (см. «Расширение VehicleWaypointService» ниже). Сообщение
`Ваш дом отмечен на карте красным чекпоинтом` (`INFO_COLOUR`, по образцу «Ваша
машина отмечена...» в `/car`). Меню НЕ переоткрывается автоматически (действие
разовое, как «Показать на карте» в `/car`); чекпоинт снимается сам при входе в
него или следующим вызовом любого указателя.

### Расширение `VehicleWaypointService`: target-режим «точка»

**Архитектурная причина.** Клиентский чекпоинт-слот игрока — ЕДИНЫЙ ресурс,
которым уже владеет `VehicleWaypointService` (бизнес-владелец слота поверх Core
`CheckpointService`; привод `VehicleWaypointSystem` снимает указатель на
уничтожении машины-цели). `HomeMenuSystem` НЕ может звать `CheckpointService`
напрямую — два хозяина слота начали бы гасить чекпоинты друг друга (например,
уничтожение машины-цели снимало бы ЧУЖОЙ, домовый чекпоинт). Поэтому сервис
расширён вторым перегруженным `showFor`:

```cpp
void showFor(IPlayer &player, IVehicle &vehicle);      // существующий: цель — машина
void showFor(IPlayer &player, const Vector3 &point);   // новый: цель — статическая точка
```

Оба режима используют ОДИН и тот же слот (`m_targets[playerId]`), пере-вызов
любого из них заменяет цель (как раньше `showFor(vehicle)` заменял прежний
указатель). Различие — в поле `vehicleId`:

- **машина** — `vehicleId = vehicle.getID()` (`>= 0`), `hasTarget = true`;
- **точка** — `vehicleId = -1`, `hasTarget = true`.

`findByVehicle(vehicleId)` (используется приводом `VehicleWaypointSystem` для
автосъёма указателя на уничтожении машины-цели) продолжает работать ТОЛЬКО для
режима «машина»: контракт `findByVehicle(-1) == -1` не изменился, поэтому цель-
точка НИКОГДА не матчится этим поиском — уничтожение любой машины в мире не
трогает указатель на точку. `hasWaypoint`/`clearFor`/`resetPlayer` — общие для
обоих режимов (флаг `hasTarget`, не завязан на `vehicleId`).

**Итог:** `HomeMenuSystem` — единственный вызывающий `showFor(point)` сейчас;
`VehicleWaypointSystem` (привод) не меняется — он и так трогает только режим
«машина».

## 3. Улучшения (заглушка)

Клик → `Улучшения пока в разработке` (`INFO_COLOUR`, единый шаблон с заглушкой
«Продать»), возврат в корень. Механика улучшений — будущее (структура карточки
«Информация» уже рассчитана на расширение под них).

## 4. Передать владение

**INPUT** «Передать владение» (тело `Введите id игрока (посмотреть можно по
TAB), которому хотите передать дом.\nОн должен быть в сети, авторизован и не
иметь своего дома.`, кнопки `Далее` / `Назад`) — тело подсказывает, ГДЕ взять id
и условия получателя (меньше слепых попыток; паттерн приглашения в семью).
`showNumberInput` (сервис сам парсит целое; мусор/пусто/overflow → повтор
показа, событийно, не цикл на сервере). Значение вне `[0, MAX_PLAYERS)` →
`Введите корректный id игрока` + повтор ввода (ошибка ВВОДА — не «нет такого
игрока»: разные причины, разные тексты).

Далее **MSGBOX** `Передача дома` (тело `Передать дом {ник}[{id}]? Все
припаркованные машины отправятся на парковку. Это действие нельзя отменить.`,
кнопки `Передать` / `Назад`) — показывается только если на момент ввода id
ре-валидация уже прошла (см. ниже); иначе — сообщение и возврат в корень БЕЗ
диалога подтверждения.

**Валидация получателя (СЕРВЕРНАЯ, ре-валидируется ДВАЖДЫ — на показе
подтверждения И на согласии MSGBOX, двойной клик/гонка):**

1. отправитель всё ещё владеет домом (`houseOf`) — иначе `У вас больше нет дома`;
2. `recipientId != playerId` — иначе `Нельзя передать дом самому себе`;
3. получатель ОНЛАЙН (`getPlayers().get(recipientId) != nullptr`) — иначе
   `Такого игрока нет в сети`;
4. у получателя АКТИВНАЯ сессия (`PlayerSessionService::getAccountId != NO_ACCOUNT`)
   — иначе `Этот игрок ещё не авторизован`;
5. получатель НЕ владеет домом (`ownsHouse`, модель «один дом на игрока» не
   нарушается) — иначе `У этого игрока уже есть свой дом`;
6. ТОЛЬКО на согласии MSGBOX: аккаунт получателя СОВПАДАЕТ со снимком на момент
   показа подтверждения (`expectedAccount`, захвачен в колбэк) — слот id мог
   занять ДРУГОЙ игрок, пока окно висело; иначе `Этот игрок сменился — начните
   передачу заново` (дом уходит только тому, чьё имя показывали в окне).

Получатель идентифицируется ТОЛЬКО серверным id + сессией — **ник НЕ вводится**
(только числовой id в INPUT), исключая путаницу «ник существует, но это другой
аккаунт»/фейковые ники.

**Действие на согласии MSGBOX** (`HomeMenuSystem::executeTransfer`, повторная
полная ре-валидация всех пяти пунктов выше — диалог мог висеть, пока всё
менялось):

1. **гейт занятости** — ни одна из припаркованных машин отправителя не занята
   водителем (`ParkedVehicleService::byVehicleId(vehicleId)` +
   `VehicleService::getDriver(vehicleId) != -1`); иначе `Пока в припаркованных
   машинах есть водители, передача недоступна` (`ERROR_COLOUR`), передача НЕ
   выполняется (частичной передачи с частью машин на парковке нет);
2. **все припаркованные записи отправителя → на парковку** — `unpark(dbId)` по
   каждой из `parkedByAccount(accountId)` (снимок списка ДО цикла — `unpark`
   правит тот же индекс, перебор живого инвалидировался бы); ПЕРЕД каждым
   `unpark` актуальный остаток бака (живой экземпляр — `VehicleService::getFuel`,
   иначе последний снимок `parked->fuel`) переносится в
   `PersonalVehicleService::setFuel` владельца — иначе следующий вызов машины с
   центральной парковки взял бы устаревший бак владения; детали — 
   `Docs/ParkedVehicles.md`, «Массовый unpark»;
3. **смена владельца** — `HouseService::setOwner(houseId, recipientKey)`; персист
   `house_owner` и перекраска иконки — подписка `HouseSystem::onOwnerChanged`
   (единая точка, см. `Docs/Houses.md`), `HomeMenuSystem` в БД не пишет;
4. **уведомления** — отправителю `Дом передан {ник}[{id}]` (`INFO_COLOUR`),
   получателю `{ник}[{id}] передал вам дом — теперь это ваш дом` (`INFO_COLOUR`).

Меню НЕ переоткрывается после передачи (у отправителя больше нет дома —
следующий `/home` у него откроет отказ гейта входа).

**Спавн-выбор «Дом»** (`Docs/SetSpawn.md`) у ОБОИХ участников перерезолвится
сам на следующем спавне (`SpawnChoiceSystem` резолвит `houseOf` заново каждый
раз) — никаких форсов делать не нужно.

## 5. Продать (заглушка)

Клик → `Продажа домов пока в разработке` (`INFO_COLOUR`), возврат в корень.
Механика цены/деньги — будущее (эта задача денег не вводит).

## 6. Выселиться

**MSGBOX** `Выселение` (тело `Выселиться из дома? Дом станет ничейным,
припаркованные машины отправятся на парковку. Это действие нельзя отменить.`,
кнопки `Выселиться` / `Назад`) — предупреждение о необратимости то же, что у
передачи (равные по тяжести действия — равный уровень предупреждения).

**Действие на согласии** (`HomeMenuSystem::executeEvict`, полная ре-валидация —
`houseOf` заново, диалог мог висеть):

1. **гейт занятости** — тот же, что у передачи; отказ `Пока в припаркованных
   машинах есть водители, выселение недоступно`;
2. **все припаркованные записи владельца → на парковку** — тот же `unpark`-цикл
   со снимком топлива в `PersonalVehicleService`, что у передачи;
3. **снятие владельца** — `HouseService::setOwner(houseId, "")`; персист (`DELETE
   house_owner`) и перекраска иконки (красная→зелёная) — тот же
   `HouseSystem::onOwnerChanged`;
4. сообщение `Вы выселились. Дом снова свободен` (`INFO_COLOUR`).

Дом снова доступен занятию ЛЮБЫМ игроком существующим путём (наступить на
пикап входа — `Docs/Houses.md`). Меню НЕ переоткрывается после выселения.

## Навигация

Пункт 1 (карточка) и подтверждения 4/6 — `Назад`/`Отмена` → корень `/home`.
После действия 2 (карта) — только сообщение, БЕЗ автоматического
переоткрытия диалога (как «Показать на карте» в `/car`; игрок при желании
открывает `/home` заново). После 3 (улучшения-заглушка)/5 (продажа-заглушка) —
сообщение И возврат в корень `/home`. После успешных 4 (передача) и 6
(выселение) — меню НЕ переоткрывается (дома больше нет).

## Три правила

- **Читер-абуз:** гейт входа и КАЖДЫЙ пункт ре-валидируют `houseOf` по
  СЕРВЕРНОМУ `accountId` из `PlayerSessionService` (не по клиентскому вводу/
  запомненному id дома) — диалог мог висеть, пока дом менял владельца из
  другого окна/сессии. **Получатель передачи** идентифицируется ТОЛЬКО
  серверным id + активной сессией: парс числа отсекает мусор (`showNumberInput`
  + диапазон `[0, MAX_PLAYERS)`), `getPlayers().get` подтверждает онлайн,
  `PlayerSessionService::getAccountId != NO_ACCOUNT` подтверждает авторизацию;
  ник НЕ вводится и нигде не участвует в резолве получателя. **Двойной
  клик/гонка передачи** — MSGBOX-согласие (`executeTransfer`) ре-валидирует
  ВСЁ заново (свой дом ещё есть, получатель не сам игрок, получатель ещё
  онлайн+авторизован, получатель ещё не владеет домом) в момент «Да», а не
  доверяет состоянию на момент показа диалога. **Модель «один дом на игрока»**
  не нарушается: получатель проверяется через `ownsHouse` и на показе
  подтверждения, и повторно на согласии. **Гейт занятости** (передача И
  выселение) не даёт `unpark`/`destroy` машину под сидящим водителем —
  `VehicleService::getDriver` читает СЕРВЕРНЫЙ факт посадки, не клиентский ввод.
  **Никаких денег** в этой задаче — «Продать» чистая заглушка без побочных
  эффектов на баланс. **Топливо при массовом unpark** переносится в
  `PersonalVehicleService` ДО уничтожения экземпляра (см. `unparkAllOf`) —
  закрывает и дюп (полный бак после «убил и передал»), и потерю (заморозка
  на низком значении).
- **Краш-безопасность:** null-гарды `IPlayer*` на каждом входе в колбэк диалога
  (`getPlayers().get` — игрок мог выйти, пока диалог висел, в т.ч. между вводом
  id и подтверждением); `HouseService::houseOf`/`getHouse` возвращают `nullptr`
  безопасно (дом мог исчезнуть/смениться); `ParkedVehicleService::byVehicleId`/
  `byDbId` — bounds-safe, `nullptr`-гард перед обращением к полям записи;
  массовый `unpark` идёт по СНИМКУ `parkedByAccount` (копия вектора), а не по
  живому индексу, который сам `unpark` правит изнутри — нет итерации по
  инвалидированному диапазону; перенос топлива ищет `ownedIndex` линейным
  проходом по `owned(playerId)` (≤ `MAX_PERSONAL_VEHICLES`) — запись могла не
  найтись (гонка/рассинхрон), тогда `setFuel` просто не вызывается, `unpark`
  всё равно идёт; персист владения (`setOwner` →
  `subscribeOwnerChanged` → БД) — на ХОЛОДНОМ пути (по диалогу), ошибки БД
  логируются и откатывают память (`Docs/Houses.md`), не валят сервер.
- **Перф:** гейт входа и каждый пункт — O(домов) через `houseOf`/`ownsHouse`
  (число домов мало, холодный путь по команде/диалогу) + O(машин владельца) на
  гейт занятости/unpark-цикл (число припаркованных ограничено `parkingCap ≤
  10`). Никаких per-tick операций — вся механика событийная (команда → диалог →
  клик).
