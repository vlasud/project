# Работа «Врач» (больница)

Бизнес-фича (НЕ Core). Код:
- `Src/Services/MedicJobService` — фаза смены, занятость 2 точек спавна скорых,
  FIFO-очередь и кулдаун лечения пациентов.
- `Src/Services/MedicWalletService` — персистентный per-account кошелёк заработка
  (write-through в БД, таблица `medic_wallet`).
- `Src/Systems/MedicJobSystem` — привод: пикап, диалог, спавн/деспавн скорых, форма,
  команда `/med`, начисление/выдача денег, per-second таймер больницы.

## Суть

Устроиться может любой у пикапа больницы. Работа не в маршруте, а в людях: врач
получает скорую, выезжает и командой `/med [id]` лечит игроков у своей машины. За
каждого вылеченного — деньги в кошелёк врача.

Маршрута нет вовсе, поэтому нет ни чекпоинтов, ни окна возврата за руль: врач
**легально ходит пешком** у своей скорой — в этом и состоит работа.

## Фазовая машина (`MedicJobService::Phase`)

```
NotWorking ──(«Начать работу»)──► Boarding  (есть свободная точка: скорая подана)
                               └► Queued    (обе точки заняты → FIFO)

Queued   ──(точка освободилась)──► Boarding
Boarding ──(скорая ОТЪЕХАЛА с точки)──► Working   (точка свободна для очереди)
Boarding ──(30 с истекло)──► Queued (скорая снята, конец очереди)

Working ──(смерть / дисконнект / «Завершить работу» / /stopjob / скорая пропала)──► NotWorking
```

Взноса за устройство нет — скорая выдаётся бесплатно.

## Две точки выезда и очередь

Расхождение с депо автобуса/развозчика: **pre-stock машин НЕТ**. Точка пустует, пока
очередь пуста; дошла очередь — на точке появляется ЛИЧНАЯ скорая работника.

Поэтому «посадка» здесь считается завершённой не по факту руля, а по факту **отъезда**
(`SPOT_RADIUS = 8` м от точки): иначе первый же врач заблокировал бы точку, сидя на
ней всю смену. Пока идёт окно `BOARDING_SECONDS = 30`, скорая отмечена красным
маркером (`VehicleWaypointService`) и на экране тикает GUI-таймер `AMBULANCE`. Не
успел — скорая снимается, работник уходит в конец очереди, точка достаётся следующему.

| Точка | X | Y | Z | угол |
|---|---|---|---|---|
| Пикап работы (иконка 22) | 1183.6260 | -1332.1185 | 13.5814 | — |
| Выезд 1 | 1180.7723 | -1338.7773 | 13.8991 | 271.2566 |
| Выезд 2 | 1180.6863 | -1308.6395 | 13.8431 | 269.4227 |

Скорая — модель `416`, цвета `1`/`3`, бак бесконечный (`setInfiniteFuel`, как у
прочего рабочего транспорта). Гейт руля серверный: за руль скорой пускают только её
работника, чужие `Owner::Work` (автобусы, грузовики) гейт пропускает.

## Форма

На устройстве выдаётся случайный скин из пула **по полу аккаунта**:

| Пол | Пул |
|---|---|
| мужской | 274, 275, 276 |
| женский | 69 |

Пол берётся из СЕССИИ (`PlayerSessionService::isFemale`), а не из текущего скина:
скин игрок мог сменить, пол аккаунта — нет. Ради этого `player.sex` теперь читается
на логине и живёт в `Session` — раньше он писался в БД при регистрации и в игру не
попадал вовсе.

Форма ставится как **БАЗА** (`PlayerSkinService::setSkin`), а не как временный скин:
временный живёт до ближайшего респавна, и первая же смерть вернула бы врача в
гражданском. Смена базы пересобирает спавн-инфо через наблюдателя. На увольнении
возвращается личный скин аккаунта (`PlayerPersonalSkinService`) — он сменой формы не
затрагивался.

## Лечение `/med [id]`

Условия (все проверяются по СЕРВЕРНОЙ правде):

1. Вызывающий — врач в фазе `Working`.
2. **И врач, и пациент — не дальше `HEAL_RADIUS = 5` м от СКОРОЙ врача**, в том же
   виртуальном мире и интерьере. Радиус считается от машины, а не от врача: лечат у
   скорой, пациента к скорой приводят. Требование к обоим — иначе врач стоял бы у
   машины и лечил через полкарты.
3. Пациент жив и **ранен**: здоровому лечение не нужно, иначе это выплата ни за что.
4. Пациента не лечили последние `HEAL_COOLDOWN = 10` минут.

Результат: HP пациента поднимается до максимума, врачу начисляется
`PAY_PER_HEAL = 100` в кошелёк (write-through), обоим уходит сообщение.

**Кулдаун принадлежит ПАЦИЕНТУ, а не врачу** — иначе двое врачей доили бы одного и
того же по очереди. Он живёт в памяти сессии и сбрасывается на её конце:
переиспользованный `playerId` чужого кулдауна не наследует.

## Деньги

Заработок копится в персистентном кошельке врача (`medic_wallet`), переживает
смерть/дисконнект/увольнение и забирается через «Забрать деньги» на пикапе больницы.
Сумма видна в общем списке `/jobwallet`; забирают её только здесь (`/jobwallet` —
справка, см. `Docs/JobWallet.md`).

## Взаимное исключение и выход

Смена держит общий лок навигации (`NavigationLockService`), поэтому совмещать врача
с автобусником/грузчиком/развозчиком нельзя — и наоборот. Прервать смену можно у
пикапа («Завершить работу») либо откуда угодно командой `/stopjob`
(см. `Docs/StopJob.md`).

## Миграция БД (выполняет ПОЛЬЗОВАТЕЛЬ)

Добавлено в `Sql/schema_all.sql` (идемпотентно). Применить на боевой БД:

```sql
CREATE TABLE IF NOT EXISTS `medic_wallet` (
    `account_id` BIGINT NOT NULL,
    `balance`    BIGINT NOT NULL DEFAULT 0,
    PRIMARY KEY (`account_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

## Константы (баланс)

| Константа | Значение | Смысл |
|---|---|---|
| `PAY_PER_HEAL` | `100` | $ за каждого вылеченного |
| `HEAL_RADIUS` | `5` м | радиус вокруг скорой для `/med` (нужен обоим) |
| `HEAL_COOLDOWN` | `10` мин | повторное лечение ОДНОГО пациента |
| `SPOT_COUNT` | `2` | точек выезда (пропускная способность) |
| `BOARDING_SECONDS` | `30` | окно «сесть и отъехать с точки» |
| `SPOT_RADIUS` | `8` м | пока машина ближе — точка занята |
| `AMBULANCE_MODEL` | `416` | скорая, цвета 1/3 |

## Три правила

- **Читер-абуз (валидация против серверных фактов):**
  - Устройство гейтится СЕРВЕРНЫМ стейтом (`PlayerState_OnFoot`), сессией и локом
    навигации.
  - `/med` целиком серверный: фаза врача, позиции обоих — ПРИНЯТЫЕ сервером
    (`PlayerLocationService` ловит телепорт-рывки), HP пациента — `PlayerHealthService`
    (клиентскому HP не верим), кулдаун — серверные часы.
  - Кулдаун на ПАЦИЕНТЕ закрывает главный вектор дойки: одного и того же игрока не
    вылечить повторно ни этим врачом, ни другим. Здоровых лечить нельзя вовсе, себя —
    тоже (id совпадает с врачом).
  - Деньги — только через `MedicWalletService::add` по серверному факту лечения;
    `add`/`withdraw` no-op без `accountId`; `withdraw` обнуляет кэш СРАЗУ (анти-дюп),
    выдача ре-валидирует сессию на клике.
  - За руль скорой — только назначенный врач (гейт по серверному стейту работы).
  - Антифлуд команды — корневой, в `PlayerCommandService` (см. `Docs/CommandFlood.md`).
- **Краш-безопасность:** все входы сервиса bounds-safe по `playerId`; конец сессии/
  смерть в ЛЮБОЙ фазе — teardown (деспавн скорой, снятие точки/очереди/маркера/
  GUI-таймера, возврат личного скина, release лока, сброс кулдауна) — ре-используемый
  `playerId` не наследует чужую смену; `get(vid)` проверяется перед разыменованием;
  `IPlayer*` из пула проверяется в очереди и async-колбэке; async-загрузка кошелька —
  serial-guard; общий per-second таймер больницы НИКОГДА не отменяется (в т.ч. из
  своего колбэка); пул машин полон — работник возвращается в очередь, точка не
  остаётся занятой без машины.
- **Перф:** геймплей событийный (пикап/диалог/команда) — PER-TICK работы нет.
  Единственный периодический — общий per-second таймер: проход по онлайну с ранним
  выходом для не-работников, для работника — сравнение квадратов дистанций, плюс
  `pumpQueue` O(`SPOT_COUNT`=2). `balanceOf` — синхронное чтение кэша без БД; запросы
  кошелька — async через `DatabaseManager` (главный поток не блокируется).

Иконка работы на миникарте стримится на `MapIconService::RADAR_STREAM_DISTANCE` —
ровно на покрытие радара: дальше она только прижималась бы к его краю, указывая на
то, чего в видимой области ещё нет.
