# Парковка личного транспорта

Парковка — бизнес-фича (НЕ Core), способ **СПАВНА** личной машины. Владение машиной
регистрирует `/pvbuy` (см. `Docs/PersonalVehicle.md`); парковка — то место, где игрок
эту машину физически вызывает. Код: `Src/Systems/ParkingSystem`. Собственного
сервиса нет (источник правды о владении — `PersonalVehicleService`, о машинах —
`VehicleService`).

## Петля

1. Игрок встаёт на **пикап парковки** (фикс. серверная точка).
2. Открывается **диалог** со списком ЕГО личных машин.
3. Игрок выбирает машину — она спавнится на **первой свободной** из 5 серверных
   точек парковки, и у неё ставится **красный чекпоинт** (ведёт к машине на
   5-местной парковке).
4. Если машина уже стоит (выбор уже заспавненной) — это **пере-спавн** (старый
   экземпляр уничтожается, новый встаёт на свободную точку, своя машина из проверки
   занятости исключается — можно встать на её же точку).
5. Машина уничтожена (серверно-САНКЦИОНИРОВАННАЯ смерть, т.е. `explode()`) — она
   **пропадает** (не висит вреком, авто-респауна нет: `respawnDelay = -1`), владение
   остаётся, машину спавнят заново ТОЛЬКО вручную через пикап. Урон, который сервер
   видит, личную не взрывает — она глохнет как все (анти-грифинг), а
   несанкционированную смерть (клиентская детонация пустой / фейковый репорт)
   `VehicleService` гасит сам: машина возвращается ЦЕЛОЙ на spawn-точку, владелец
   её не теряет. Подробности — `Docs/PersonalVehicle.md`
   («Смерть машины») и `Docs/Vehicles.md` («Контракт смерти»).

## Диалог выбора (`DialogStyle_LIST`)

- Открывается, если у игрока есть хотя бы одна машина; иначе сообщение
  (см. таблицу ниже).
- Заголовок: `Личный транспорт`. Кнопки: слева `Взять`, справа `Закрыть`.
- Строка пункта: `{n}. {имя}  —  {статус}`, где `{n}` с 1, `{статус}` по
  `ParkedVehicleService::parkedMode(dbId)`: `у дома` (припаркована лично) / `в семье`
  (расшарена) / `в гараже` (`vehicleId == -1`, не припаркована) / `вызвана`
  (`vehicleId != -1`, в мире). Пример: `1. Infernus  —  в гараже`. Статус `вызвана`
  (а не «на парковке») — единый словарь с `/car` (см. `Docs/CarMenu.md`): машина может
  стоять где угодно.
- `{имя}` — из справочника `VehicleModelNames::displayName(model)`
  (см. `Docs/Vehicles.md`, «Каталог имён моделей»; правило словаря —
  `Docs/GameDesign/UI_Texts.md`, «Имена машин для игрока»): каноническое английское
  имя SA-MP, при пустом имени (модель вне 400..611 — битые данные) — фолбэк
  `Модель {id}` (пустую строку игроку не показываем). Нумерация и статусы прежние.
- Колбэк берёт **живого игрока** (`getPlayers().get(playerId)`) и **перепроверяет**
  индекс против актуального `owned()` (владение могло измениться); **припаркованную у
  дома машину НЕ спавнит** (`ParkedVehicleService::isParked(dbId)` → сообщение «Эта
  машина припаркована у дома»): она статична у дома (личная ИЛИ расшаренная), личный
  спавн дал бы дубль. Финальную валидацию индекса делает
  `PersonalVehicleService::spawn`.

## Выбор свободной точки

«Занято» = любая машина физически в **горизонтальном** радиусе
`SPOT_OCCUPIED_RADIUS = 3.0 м` от **любой из 3 проб** места
(`VehicleService::anyVehicleNear`, сравнение по квадрату дистанции). При
**пере-спавне** своя машина исключается во **всех** пробах
(`anyVehicleNear(..., currentVehicle(playerId, ownedIndex))`) — игрок может встать
на её же точку.

### 3-пробная проверка занятости (центр + вперёд + назад)

Место — **прямоугольник** (машина ~4.5 м длиной), а `anyVehicleNear` — **круг**
радиуса `3.0`. Одна круговая проба от ЦЕНТРА (Y±3.0) упускала бы чужую машину,
подтянутую к **переднему**/**заднему** краю места. `isSpotFree` делает **3 пробы**
и считает место свободным, только если **все три** дали `false`:

- **центр** — `spot.position`;
- **вперёд** — центр `+ SPOT_PROBE_OFFSET` по ориентации места;
- **назад** — центр `- SPOT_PROBE_OFFSET` по ориентации.

Направление «вперёд» — SA-MP конвенция проекта (та же, что
`HouseService::backOf`): «вперёд» = `(-sin(a), cos(a))`, «назад» = `(sin(a),
-cos(a))`, `a = spot.angle * PI/180` в **радианах**. Пробы считаются в **2D (XY)**,
Z берётся у центра (занятость горизонтальная — `anyVehicleNear` игнорирует Z).

**`SPOT_PROBE_OFFSET = 2.0 м`** — геометрия:

- *Покрытие длины места.* Центр ловит Y±3.0; пробы ±2.0 дотягивают радиус до Y±5.0
  вдоль ориентации — машина у любого края прямоугольника (~4.5 м) попадает.
- *Нет ложного занятия соседнего места в ряду.* Все 5 точек — в ряд по X с шагом
  ~4.45 м, `angle 0` -> «вперёд» = **+Y** (перпендикулярно ряду). Дистанция от
  вперёд/назад-пробы до origin соседа = √(4.45² + 2.0²) = **4.88 м** > радиуса
  `3.0`; ближайшая точка кузова соседской машины (полуширина ~0.9 по X) — ≥ 3.55 м
  по X > `3.0`. Соседнее место занятым не считается.
- *Проезжая часть перед/за рядом.* Пробы идут вдоль ориентации (по Y), а не по X;
  при `angle 0` они уходят к переднему/заднему краю САМОГО места, а не в соседнее.
  `2.0` (< полудлины места) не выносит центр пробы за пределы места настолько,
  чтобы систематически ловить проезжающие машины; приоритет — поймать машину НА
  месте без грубых ложных срабатываний от соседей.

Занятость считается через **`GridService`** (пространственный индекс машин,
`GridEntityType::Vehicle`), а НЕ проходом по всему пулу: `anyVehicleNear` спрашивает
у грида соседей-машин (`forEachInRadius`) — O(машин в соседних ячейках), без
аллокаций. Машины ведёт в гриде `GridSystem`: add на создании, remove на
уничтожении, а **move на ВСЕХ путях смены позиции** —
- под водителем — driver-апдейт (`onPlayerUpdate`, `getSeat == 0`);
- **респаун** — `VehicleService::onVehicleRespawn` (ядро уже на spawn-позиции);
- **принятый unoccupied-синк** (толчок/дрейф пустой машины) — `validateUnoccupied`
  при accept, по позиции ИЗ апдейта.

Респаун и принятый unoccupied идут в грид через наблюдателя
`VehicleService::subscribeMoved(observer)` (см. `Docs/Vehicles.md`). Без него грид
застревал бы на старой позиции (после респауна/толчка машина физически у точки, а
индекс её там не видит) — и `anyVehicleNear` ложно считал бы точку свободной, спавня
вторую машину поверх. ОТКЛОНЁННЫЙ читерский unoccupied-апдейт в грид НЕ попадает
(наблюдателя зовём только на accept). Запрос к гриду 3D с запасом по Z
(`GRID_VERTICAL_SLACK = 30 м`): машина оседает на грунт со своей Z, точки заданы на
фикс. высоте — без запаса 3D-предфильтр отбросил бы кандидата, чья XY в радиусе, но
Z отличается; ФИНАЛЬНАЯ проверка всё равно XY. Зависимость `GridService` сервис
получает в `VehicleService::bind` (передаёт `VehicleSystem::initialize` из реестра).

- Берётся ПЕРВАЯ точка, где `isSpotFree(...)` (порядок таблицы выше).
- Нет свободной → отказ, существующие машины НЕ трогаем.

Проверка занятости **ГОРИЗОНТАЛЬНАЯ (XY), Z игнорируется.** Точки заданы с
`Z ≈ 24.55` (5-я — `23.80`), а машина при спавне **оседает на грунт** со своей Z:
прежняя 3D-проверка раздувала дистанцию Z-разницей выше радиуса и НЕ детектила
рядом стоящую машину — личная спавнилась ПОВЕРХ уже стоящей (напр. поставленной
дев-командой `veh`). Считаем только `delta.x²+delta.y² ≤ radius²`. Радиус поднят с
`2.5` до `3.0`: надёжно ловит машину у точки по её длине (~4.5 м), а соседние точки
в ~4.45 м (origin соседа за радиусом) — ложного занятия соседней точки нет.

Поиск свободной точки — серверный расчёт; не зависит от клиента.

## Красный чекпоинт-указатель (общий `VehicleWaypointService`)

Бухгалтерию чекпоинта у поданной машины ведёт **общий `VehicleWaypointService`**
(бизнес-фича вне Core; тот же слот переиспользует `/car`, см. `Docs/CarMenu.md`) —
раньше её вела сама `ParkingSystem`. Парковка на ветке `Ok` спавна лишь ставит
указатель: `m_waypointService.showFor(player, *veh)`. Стандартный наземный чекпоинт,
радиус `VehicleWaypointService::CHECKPOINT_RADIUS = 3.0` (`CheckpointService::
setForPlayer`). Жизненный цикл (снятие) целиком в сервисе/его приводе
`VehicleWaypointSystem`:

- **вход** игрока в чекпоинт (`onEnter` → `clearFor`);
- **уничтожение** машины-цели (`VehicleWaypointSystem` подписан на
  `VehicleService::subscribeDestroyed`: `findByVehicle` → живой игрок `clearFor` /
  вышел `resetPlayer`);
- **пере-вызов** (пере-спавн через парковку ИЛИ повторный `/car`): `showFor`
  заменяет прежний указатель (`setForPlayer` перерисует слот);
- **дисконнект**: `VehicleWaypointSystem::onPlayerDisconnect` → `resetPlayer`
  (клиентский чекпоинт сбросит сам `CheckpointService`).

Снятие из `onEnter` безопасно: `CheckpointService` копирует обработчик ДО вызова
(нет ре-энтрантной порчи слота). Один слот на игрока — парковка и `/car` не
«дерутся»: пере-вызов всегда оставляет ровно один указатель.

## Персист

Парковка САМА ничего не хранит между сессиями (точки/пикап — статика в коде).
Право владения машинами (и персистентный остаток топлива) персистится в БД на
стороне `PersonalVehicleService` (`personal_vehicle`, колонка `fuel`; см.
`Docs/PersonalVehicle.md`, «Персист топлива»), а машина-сущность в мире —
сессионная (подаётся заново через парковку). При росте онлайна 5 мест станут узким
горлом — решение: добавлять парковочные ЗОНЫ, не расширять одну парковку.

**Пере-спавн переносит остаток топлива.** `PersonalVehicleService::spawn` снимает
`getFuel` старого экземпляра ДО его уничтожения и применяет сохранённый остаток к
новому (поверх дефолтного полного бака от `create`) — «убрать в гараж (пере-спавн
через ту же кнопку) → вызвать заново» не доливает бак бесплатно. Первая покупка
(ещё не сохранённого остатка нет) даёт полный бак — это норма, не дыра.

## Три правила

- **Читер-абуз:** точки спавна и пикап — СЕРВЕРНЫЕ (фикс. 5 точек, 1 пикап); игрок
  спавнит ТОЛЬКО свои машины (владение серверное по `playerId`, индекс валидируется
  в `PersonalVehicleService::spawn`); произвольную позицию задать нельзя — координаты
  берёт сервер; занятость — серверный расчёт (3 пробы того же `anyVehicleNear`,
  клиент на неё не влияет), своя машина исключается во всех пробах; лимит
  `MAX_PERSONAL_VEHICLES` форсится; модель валидируется при
  покупке (вкл. 569/570); машина создаётся только через `VehicleService::create`
  (`Owner::Player`); свободная точка — серверный расчёт; диалог/пикап-колбэки берут
  живого игрока и перепроверяют владение (могло измениться). Пикап — edge-триггер
  (диалог разово при входе, не переоткрывается пока игрок стоит).
- **Краш/UB:** bounds `playerId`/`ownedIndex`/индекса точки; null-гарды
  (`getPlayers().get`, `veh`, `m_vehicles->get` в `anyVehicleNear`); ре-энтрантность
  `spawn`/`reset` ↔ `onWorldVehicleDestroyed` (запись владения НЕ удаляется →
  индекс стабилен; `reset` копирует+чистит до `destroy`); чекпоинт-указатель без
  висячих хэндлов — снятие на входе/уничтожении/пере-вызове/дисконнекте ведёт общий
  `VehicleWaypointService`/`VehicleWaypointSystem` (снятие из `onEnter` безопасно —
  обработчик копируется до вызова; `showFor` ставит указатель только при валидном
  `veh` на ветке `Ok`); `anyVehicleNear` — null-гард `m_grid`/`m_vehicles`,
  bounds+exists-гард кандидата из грида, `get`-гард; visit грид во время обхода НЕ
  модифицирует.
- **Перф:** пикап/диалог/спавн — ХОЛОДНЫЙ путь (по вводу); проверка занятости — 3
  пробы на точку (было 1) -> до `5×3 = 15` вызовов `anyVehicleNear` на спавн (раньше
  ≤5), но каждый — O(машин в соседних ячейках) через `GridService::forEachInRadius`
  (а не O(пул=2000)), без аллокаций; `isSpotFree` без состояния, `sin`/`cos` конечны.
  Чекпоинт-указатель per-player (`showFor`/`clearFor` — O(1)); PER-TICK работы НЕТ.
