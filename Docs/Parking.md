# Парковка личного транспорта

Парковка — бизнес-фича (НЕ Core), способ **СПАВНА** личной машины. Владение машиной
регистрирует `/pvbuy` (см. `Docs/PersonalVehicle.md`); парковка — то место, где игрок
эту машину физически вызывает. Код: `Src/Systems/ParkingSystem`. Собственного
сервиса нет (источник правды о владении — `PersonalVehicleService`, о машинах —
`VehicleService`).

## Петля

1. Игрок встаёт на **пикап парковки** (фикс. серверная точка).
2. Открывается **диалог** со списком ЕГО личных машин.
3. Игрок выбирает машину — она спавнится на **первой свободной** из 5 серверных
   точек парковки, и у неё ставится **красный чекпоинт** (ведёт к машине на
   5-местной парковке).
4. Если машина уже стоит (выбор уже заспавненной) — это **пере-спавн** (старый
   экземпляр уничтожается, новый встаёт на свободную точку, своя машина из проверки
   занятости исключается — можно встать на её же точку).
5. Машина уничтожена (РЕАЛЬНАЯ смерть) — она **пропадает** (не висит вреком,
   авто-респауна нет: `respawnDelay = -1`), владение остаётся, машину спавнят заново
   ТОЛЬКО вручную через пикап. Урон личную не взрывает — она глохнет как все
   (анти-грифинг), поэтому реальное уничтожение редко. Подробности — в
   `Docs/PersonalVehicle.md` («Смерть машины»).

## Пикап + 3D-текст

- **Пикап:** модель `1239` (info-икона «i» — сервис-точка, не машина-икона),
  тип `PickupType 1` (подбор по касанию, всегда виден — как пикапы домов/баз).
  Создаётся в `initialize` (vw 0) через `PickupService::add`, обработчик
  `onParkingPickup`. Cooldown подбора — дефолтный сервиса (1000 мс).
- **3D-текст** над пикапом (`TextLabelService::add`, цвет `INFO {120,220,255}`,
  drawDistance `25.0`, testLOS `false`), текст (через `u()`):
  ```
  Парковка
  {B4DCFF}Возьмите свой транспорт
  ```
  `{B4DCFF}` — клиентский цветовой код (не игроковый текст, чистить не нужно).

## Диалог выбора (`DialogStyle_LIST`)

- Открывается, если у игрока есть хотя бы одна машина; иначе сообщение
  (см. таблицу ниже).
- Заголовок: `Личный транспорт`. Кнопки: слева `Взять`, справа `Закрыть`.
- Строка пункта: `{n}. Модель {model}  —  {статус}`, где `{n}` с 1, `{статус}` =
  `в гараже` (`vehicleId == -1`) / `на парковке` (`vehicleId != -1`). Пример:
  `1. Модель 411  —  в гараже`.
- Имя машины SA не показываем (таблицы имён в гейммоде нет) — `Модель {id}`. Когда
  появится справочник имён — заменить, формат не меняется.
- Колбэк берёт **живого игрока** (`getPlayers().get(playerId)`) и **перепроверяет**
  индекс против актуального `owned()` (владение могло измениться); финальную
  валидацию индекса делает `PersonalVehicleService::spawn`.

## Выбор свободной точки

«Занято» = любая машина физически в **горизонтальном** радиусе
`SPOT_OCCUPIED_RADIUS = 3.0 м` от точки (`VehicleService::anyVehicleNear`, сравнение
по квадрату дистанции). При **пере-спавне** своя машина исключается
(`anyVehicleNear(..., currentVehicle(playerId, ownedIndex))`) — игрок может встать
на её же точку.

- Берётся ПЕРВАЯ точка, где `!anyVehicleNear(...)` (порядок таблицы выше).
- Нет свободной → отказ, существующие машины НЕ трогаем.

Проверка занятости **ГОРИЗОНТАЛЬНАЯ (XY), Z игнорируется.** Точки заданы с
`Z ≈ 24.55` (5-я — `23.80`), а машина при спавне **оседает на грунт** со своей Z:
прежняя 3D-проверка раздувала дистанцию Z-разницей выше радиуса и НЕ детектила
рядом стоящую машину — личная спавнилась ПОВЕРХ уже стоящей (напр. поставленной
дев-командой `veh`). Считаем только `delta.x²+delta.y² ≤ radius²`. Радиус поднят с
`2.5` до `3.0`: надёжно ловит машину у точки по её длине (~4.5 м), а соседние точки
в ~4.45 м (origin соседа за радиусом) — ложного занятия соседней точки нет.

Поиск свободной точки — серверный расчёт; не зависит от клиента.

## Красный чекпоинт (per-player)

Состояние per-player: `{ active, vehicleId цели }`. Стандартный наземный чекпоинт,
радиус `3.0` (`CheckpointService::setForPlayer`). Жизненный цикл (снятие):

- **вход** игрока в чекпоинт (`onEnter` → `clearCheckpoint`);
- **уничтожение** машины-цели (`VehicleService::subscribeDestroyed`: если у игрока
  активен чекпоинт на этот `vehicleId` — снять);
- **пере-спавн**: уничтожение старой машины снимает старый чекпоинт (через тот же
  destroyed-наблюдатель), затем `setForPlayer` ставит новый у новой точки;
- **дисконнект**: слот чекпоинта гасится (клиентский чекпоинт сбросит сам
  `CheckpointService`).

`clearCheckpoint` снимает только активный чекпоинт (иначе no-op), берёт живого
игрока, bounds-safe по `playerId`. Снятие из `onEnter` безопасно: `CheckpointService`
копирует обработчик ДО вызова (нет ре-энтрантной порчи слота).

## Персист

Парковка САМА ничего не хранит между сессиями (точки/пикап — статика в коде).
Право владения машинами персистится в БД на стороне `PersonalVehicleService`
(`personal_vehicle`; см. `Docs/PersonalVehicle.md`), а машина-сущность в мире —
сессионная (подаётся заново через парковку). При росте онлайна 5 мест станут узким
горлом — решение: добавлять парковочные ЗОНЫ, не расширять одну парковку.

## Три правила

- **Читер-абуз:** точки спавна и пикап — СЕРВЕРНЫЕ (фикс. 5 точек, 1 пикап); игрок
  спавнит ТОЛЬКО свои машины (владение серверное по `playerId`, индекс валидируется
  в `PersonalVehicleService::spawn`); произвольную позицию задать нельзя — координаты
  берёт сервер; лимит `MAX_PERSONAL_VEHICLES` форсится; модель валидируется при
  покупке (вкл. 569/570); машина создаётся только через `VehicleService::create`
  (`Owner::Player`); свободная точка — серверный расчёт; диалог/пикап-колбэки берут
  живого игрока и перепроверяют владение (могло измениться). Пикап имеет cooldown
  подбора.
- **Краш/UB:** bounds `playerId`/`ownedIndex`/индекса точки; null-гарды
  (`getPlayers().get`, `veh`, `m_vehicles->get` в `anyVehicleNear`); ре-энтрантность
  `spawn`/`reset` ↔ `onWorldVehicleDestroyed` (запись владения НЕ удаляется →
  индекс стабилен; `reset` копирует+чистит до `destroy`); чекпоинт без висячих
  хэндлов (снятие на входе/уничтожении/пере-спавне/дисконнекте; снятие из `onEnter`
  безопасно — обработчик копируется до вызова); `anyVehicleNear` — безопасный проход
  по пулу (exists-проверка + `get`-гард).
- **Перф:** пикап/диалог/спавн — ХОЛОДНЫЙ путь (по вводу); `anyVehicleNear` —
  O(пул=2000) только на спавне (редко, по выбору в диалоге), без аллокаций;
  чекпоинт per-player; PER-TICK работы НЕТ.
