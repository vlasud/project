# Меню игрока `/mn` и репорт

Код: `Src/Services/Core/ReportService` (источник правды кулдауна репортов +
журнал), `Src/Systems/Core/MenuSystem` (команда `/mn`, диалоги, рассылка
репорта), help-слой — `Src/Systems/Core/HelpSystem/HelpDialog.{h,cpp}`.
Дизайн-спецификация и ВСЕ тексты — `Docs/GameDesign/PlayerMenu.md` и
`Docs/GameDesign/UI_Texts.md` (раздел «Меню игрока /mn и репорт»).

`/mn` — единая стартовая панель для ВСЕХ игроков (`Kind::None`): «Информация» /
«Связь с администрацией» / «Помощь». Навигация — по образцу `/faction`
(LIST-корень, подменю с «Назад», переоткрытие диалога при невалидном вводе).

## Где живёт

- **`ReportService` (core).** Пер-игрок `std::array<State, MAX_PLAYERS>`: момент
  последнего успешного обращения + флаг «был хоть один репорт». Кулдаун (память,
  сессия сервера) и запись в файл-лог — здесь; рассылку сервис НЕ делает (у
  сервисов нет доступа к игрокам/ICore). Зарегистрирован в `ServiceRegister`
  рядом с `PlayerCommandService`.
- **`MenuSystem` (core-система).** `PlayerConnectEventHandler` (для сброса
  кулдауна на дисконнекте) + `BaseSystem`. Зависимости из регистра:
  `PlayerCommandService`, `FactionService`, `PlayerDialogService`, `AdminService`,
  `ReportService`, `PlayerChatService`. Перебор игроков для рассылки — через
  `m_core.getPlayers().entries()`.

## Разнесение: кулдаун+лог (сервис) vs. рассылка (система)

- `ReportService::ready(id, now)` / `secondsLeft(id, now)` — кулдаун (ceil
  остатка, как в антифлуде команд). `record(id, now, name, text)` — ставит
  кулдаун (`lastReportAt = now`) И пишет `LogManager::log(LogLevel::Message,
  "[REPORT] {name}[{id}]: {text}")` (text — уже utf-8 после санитизации).
  `reset(id)` — сброс слота.
- `MenuSystem` владеет рассылкой: один проход по `entries()`, каждому онлайн с
  `AdminService::isLoggedIn` шлёт `[Репорт] {ник}[{id}]: {текст}` цветом
  `ADMIN_COLOUR`, считает `count`. Затем зовёт `ReportService::record` (кулдаун +
  журнал — обращение пишется в лог даже при `count == 0`). Игроку: `count > 0` —
  «Обращение отправлено администрации. Ожидайте ответа.»; `count == 0` — «Сейчас
  администраторов нет онлайн. Обращение сохранено, его рассмотрят позже.»
  (`INFO_COLOUR`).

## Help-слой (общий для /help и пункта «Помощь»)

Построение ТЕЛА help-диалога вынесено из приватного `HelpSystem::cmdHelp` в
свободную функцию `buildHelpDialogBody(const PlayerCommandService&, const
FactionService&, int playerId)` (`HelpDialog.{h,cpp}`): `collectHelpCommands` →
фильтр секции «Фракция» по `getMemberFaction(id) != NO_FACTION` → сортировка по
`categoryOrder`/имени → сборка tablist-тела с жёлтыми разделителями
(`categoryOrder`/`categoryLabel` перенесены туда). Возвращает utf-8 (БЕЗ `u()` —
кодирует вызывающий при сборке Dialog).

`HelpSystem::cmdHelp` теперь зовёт `buildHelpDialogBody`, затем строит Dialog
(`TABLIST_HEADERS`, title «Команды», `u(body)`, left «Закрыть»). **Поведение
/help не изменилось** — тот же результат, та же логика, просто тело собирается
общей функцией. Пункт «Помощь» меню `/mn` строит точно такой же диалог из той же
функции — расхождению неоткуда взяться. Из help-диалога в `/mn` НЕ возвращаемся
(решение ГД: `/help` — самостоятельный экран с кнопкой «Закрыть»).

## Навигация

```
/mn  (LIST: «Меню игрока»; left «Выбрать», right «Закрыть»)
 ├─ 0 Информация            → TABLIST «Поле|Значение»; left «Назад» → /mn
 ├─ 1 Связь с администрацией → INPUT; left «Отправить»; right «Назад» → /mn
 └─ 2 Помощь                → help-диалог (= /help); left «Закрыть» завершает
```

«Информация» — серверные факты из `FactionService`: `Имя` = `getName()`;
`Организация` = `getFaction(getMemberFaction(id))->name` или «Гражданин» при
`NO_FACTION`; `Должность` = `getMemberRank(id)->name` (+ « (лидер)» если
`isLeader`) или «—». id игрока в карточке не показываем.

## Валидация и кулдаун репорта (константы баланса)

| Параметр | Значение | Где |
|----|----|----|
| `ReportService::REPORT_COOLDOWN` | `60` сек | кулдаун между УСПЕШНЫМИ обращениями |
| `REPORT_MAX_BYTES` (MenuSystem) | `180` байт utf-8 (~90 кир.) | обрезка `sanitizeUserText`, как `/a`/`/an` |
| `REPORT_MIN_CHARS` (MenuSystem) | `3` видимых символа | минимум после чистки |

Логика «Отправить»:

1. `response != Left` (Назад) → `showMenu`.
2. `!ReportService::ready(id, now)` → «До следующего обращения: {N} сек.»
   (`secondsLeft`), выход (диалог закрыт — не зацикливаем).
3. `PlayerChatService::isMuted(id)` → «Чат заблокирован. Осталось: {N} сек»
   (замученному репорт не даём; репорт идёт мимо общего чат-пути — иначе мут его
   не глушит). Та же формулировка, что у блока чата.
4. Санитизация `sanitizeUserText(cp1251Toutf8(input), 180)`. `visibleLength < 3`
   (число utf-8 кодпойнтов) → «Сообщение слишком короткое» + переоткрыть INPUT.
5. Иначе — рассылка залогиненным админам онлайн + `record` (кулдаун ставится
   ТОЛЬКО здесь, на успешную отправку) + подтверждение игроку.

Цвета (локальные в `MenuSystem.cpp`): `ADMIN_COLOUR = 0xFFB400FF` для строки
`[Репорт]` админам; `INFO_COLOUR{120,220,255}` для подтверждений игроку.

## Сброс кулдауна

`MenuSystem::onPlayerDisconnect` зовёт `ReportService::reset(id)` — иначе кулдаун
утёк бы в переиспользованный слот (и баг — у нового игрока пауза без репортов, и
абьюз). По образцу `AntiCheatSystem`/`ChatSystem` (`PlayerConnectEventHandler`).

## Три правила

- **Читер-абуз / спам:** кулдаун 60 с (`ready`/`record`) против спама РАЗНЫМИ
  текстами (корневой антифлуд ловит лишь байт-в-байт одинаковые строки подряд,
  репорт же шлётся из диалога разными текстами); санитизация против инъекций
  (вырезается `\t` — разделитель tablist — и управляющие) и переполнения (лимит
  180 байт по границе utf-8); все данные карточки «Информация» — серверные факты
  `FactionService`, не клиентский ввод; рассылка только залогиненным админам
  (`isLoggedIn`) — состав/каналы админки наружу не палятся; замученному репорт
  закрыт.
- **Краш:** bounds-guard `0..MAX_PLAYERS` в `ReportService`; все callback'и
  диалогов перепроверяют `m_core.getPlayers().get(id)` (игрок мог выйти, пока
  открыт диалог) и работают с локальной копией id; рассылка только по `entries()`
  с null-check каждого `IPlayer*`; путь синхронный (на главном потоке), без
  async-гонок и реэнтрантности; `reset` на дисконнекте.
- **Перф:** всё холодный путь (по команде/диалогу), не per-tick. Рассылка —
  O(online); help-тело собирается только при открытии. На горячем пути кода нет.
