# Экранные попапы через textdraw (ScreenNoticeService)

Инфраструктурный (Core) сервис показа транзиентных текстовых попапов на
экране игрока: ОДИН per-player textdraw на игрока (единая экранная область),
серверный таймер гашения, минимальное время показа и приоритет нового
сообщения. Бизнес-агностик — сам не решает, что и когда показать, только умеет
показать/погасить по запросу консюмера (текст + цвет + длительность).

Код: `Src/Services/Core/ScreenNoticeService/ScreenNoticeService.{h,cpp}`,
`Src/Systems/Core/ScreenNoticeSystem/ScreenNoticeSystem.{h,cpp}`. Регистрация —
`Src/Services/ServiceRegister.cpp` (после `TextDrawService` и `TimerService`),
`Src/Systems/SystemRegister.cpp` (рядом с `GameTextSystem`).

## Почему не native GameText

Native `sendGameText`/`hideGameText` open.mp управляем ТОЛЬКО через компонент
`Fixes`, которого на этом сервере нет. Без него `sendGameText` уходит клиенту
сырым RPC — клиент GTA:SA полностью игнорирует серверный `time` и проигрывает
СВОЮ fade-анимацию (у крупных стилей — порядка 6 секунд), и `hideGameText` её
не прерывает. Итог: попапы (имя машины, «двигатель сломан») висели по
собственному клиентскому таймеру вне зависимости от того, что просил сервер.

Вместо этого рисуем свой textdraw-попап: сервер полностью контролирует и
момент показа, и момент гашения (свой таймер), и может мгновенно прервать
старый попап новым.

## Макет

Один фиксированный макет на всех консюмеров (экспорт /td-редактора проекта):
низ-право экрана, шрифт 3, без бокса, `letterColour` макета — лишь ДЕФОЛТ
(перекрывается параметром вызова):

| Параметр       | Значение             |
|----------------|-----------------------|
| Позиция        | `{624, 333}`          |
| Alignment      | `Right`               |
| Style          | `TextDrawStyle_3`     |
| LetterSize     | `{0.625, 2.5}`        |
| TextSize       | `{400, 17}`           |
| Box            | нет                    |
| Дефолт-цвет    | белый (`Colour::White()`), перекрывается параметром `show()` |

Новый вид попапа НЕ требует нового макета/слота — только вызывающий передаёт
свои текст/цвет/длительность.

## API

```cpp
m_screenNotice.show(player, text, duration, colour /* = Colour::White() */);
m_screenNotice.hide(player); // погасить раньше срока, очистить pending
```

- `text` — уже готовая строка (cp1251 для кириллицы, санитизацию делает
  `TextDrawService` — длина, управляющие символы, парность `~`; тильда-коды
  `~r~` в textdraw НЕ интерпретируются — цвет только параметром `colour`).
- `duration` — клампится к `[MIN_DISPLAY, MAX_DISPLAY]` = `[1000ms, 60000ms]`.
- `colour` — цвет текста этого конкретного показа (дефолт — белый).

## Поведение — минимальное время показа + приоритет нового

Один персистентный per-player textdraw на игрока, лениво создаётся при первом
`show()` и переиспользуется (`setText`+`setColour`+`show()`), без пересоздания.

- **Ничего не показано** — новое сообщение выводится сразу.
- **Показано ≥ `MIN_DISPLAY` (1с)** — новое сообщение заменяет немедленно:
  `setColour` + `setText` + `show()` поверх текущего, БЕЗ промежуточного
  `hide()` (не мигает). `setColour` per-player textdraw сам клиенту ничего не
  шлёт — обязателен повторный `show()`, который пересылает textdraw целиком.
- **Показано < `MIN_DISPLAY`** — новое сообщение становится ОТЛОЖЕННЫМ (очередь
  глубины 1: повторный `show()` до свапа молча заменяет предыдущий pending) и
  выходит на экран РОВНО в момент `shownAt + MIN_DISPLAY`, независимо от
  исходного `duration` текущего показа.
- **Гашение по duration** — если на этот момент есть pending, он показывается
  немедленно вместо гашения; иначе textdraw скрывается.
- **`hide(player)`** — гасит немедленно, отменяет таймер и очищает pending.

Реализация — один `TimerService::Handle` на игрока: пока pending пуст, он
отсчитывает `duration` текущего показа; как только назначается pending, таймер
перепланируется на остаток до `shownAt + MIN_DISPLAY` (исходный `duration`
текущего показа с этого момента не важен — он гарантированно вытесняется на
границе минимального времени).

## Таймер и дисконнект

Таймер — `TimerService::setPlayerTimeout`: колбэк получает гарантированно
живого `IPlayer&`, при дисконнекте таймер отменяется автоматически ядром
`TimerService`. Per-player textdraw умирает вместе с пулом игрока — `destroy`
не требуется. `ScreenNoticeSystem::onPlayerDisconnect` лишь сбрасывает
сохранённое состояние игрока (`resetPlayer`: id textdraw, pending, флаг
показа), чтобы переиспользованный id следующего игрока не унаследовал чужой
textdraw/pending.

## Три правила

- **Читер-абуз.** Чистая косметика: сообщение сервер -> клиент, никакой
  игровой логики/анти-чита от попапа не зависит. Показ вызывается консюмером
  на СЕРВЕРНЫЙ факт (имя машины из каталога, поломка двигателя, ник из
  NicknameService) — сам сервис клиентского ввода не принимает. Нагрузка
  ограничена структурно: не более одного видимого + одного pending сообщения и
  ОДНОГО таймера на игрока — спам вызовов `show()` не растит очередь.
- **Краш-безопасность.** `playerId` — bounds-чек перед доступом к массиву
  состояний. `createForPlayer` может вернуть `nullptr` (пул per-player
  textdraw исчерпан) — попап тихо не показывается, `textDrawId` остаётся `-1`.
  Гашение/свап — через `setPlayerTimeout`, дисконнект в колбэке закрыт ядром.
  Состояние сбрасывается на дисконнекте, чтобы не работать с чужим/протухшим
  textdraw id.
- **Перф.** Событийно — вызывается по факту консюмера, не per-tick. Один
  `TimerService::Handle` на игрока (не более 2, требование выполнено с
  запасом). Textdraw создаётся лениво один раз и переиспользуется — O(1) на
  вызов, без лишних аллокаций/RPC создания (кроме копии строки pending, если
  сообщение отложено).
