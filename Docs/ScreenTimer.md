# Экранный таймер обратного отсчёта (ScreenTimerService)

Инфраструктурный (Core) сервис показа игроку ОДНОГО активного таймера обратного
отсчёта как textdraw-бара (верх-центр экрана). Это **дисплей-слой**: сервис сам
ничего не отсчитывает и не запускает игровых таймеров — источник правды о времени
остаётся в бизнес-системе, которая пушит остаток раз в секунду из своего тика.
Бизнес-агностик: умеет только показать/обновить/погасить бар по запросу (остаток в
секундах + опциональная англ. метка).

Код: `Src/Services/Core/ScreenTimerService/ScreenTimerService.{h,cpp}`,
`Src/Systems/Core/ScreenTimerSystem/ScreenTimerSystem.{h,cpp}`. Регистрация —
`Src/Services/ServiceRegister.cpp` (после `TextDrawService`),
`Src/Systems/SystemRegister.cpp` (рядом с `ScreenNoticeSystem`).

Отдельный слот от `ScreenNoticeService`: тот — транзиентные попапы (низ-право), этот —
персистентный бар отсчёта (верх-центр). Оба — свои per-player textdraw, показываются
одновременно и не конфликтуют.

## Макет

Один фиксированный макет (пресет `/td`-редактора геймдизайнера,
`Server/textdraws/timer.txt`). Поля перенесены в код **именованными значениями**
`ScreenTimerService::layout()` (файл в рантайме НЕ читается). Расшифровка пресета
СТРОГО по формату сериализации `TextDrawEditorSystem::serializeItems` (поле → значение):

Строка пресета:
```
td 320.00 114.00 2 3 0.7031 2.8125 400.00 17.00 FFFFFFFF 00000080 000000FF 0 1 0 0 0 0 0.00 0.00 0.00 1.000 -1 -1 1
```

| # | Поле формата | Значение | Смысл |
|---|---|---|---|
| — | kind | `td` | строка textdraw |
| 1 | `pos.x` | `320.00` | X (центр экрана 640) |
| 2 | `pos.y` | `114.00` | Y (верх) |
| 3 | `alignment` | `2` | `TextDrawAlignment_Center` |
| 4 | `style` | `3` | `TextDrawStyle_3` (Pricedown) |
| 5 | `letterSize.x` | `0.7031` | ширина буквы |
| 6 | `letterSize.y` | `2.8125` | высота буквы |
| 7 | `textSize.x` | `400.00` | ширина области/бокса (для center — база центрирования) |
| 8 | `textSize.y` | `17.00` | высота области/бокса |
| 9 | `letterColour` | `FFFFFFFF` | белый текст |
| 10 | `boxColour` | `00000080` | чёрный, alpha 128 (полупрозрачный) |
| 11 | `backgroundColour` | `000000FF` | чёрный, alpha 255 |
| 12 | `box` | `0` | **бокс ВЫКЛЮЧЕН** |
| 13 | `proportional` | `1` | пропорциональный |
| 14 | `selectable` | `0` | не кликабельный |
| 15 | `shadow` | `0` | без тени |
| 16 | `outline` | `0` | без контура |
| 17 | `previewModel` | `0` | (не превью) |
| 18–20 | `previewRotation` | `0 0 0` | (не превью) |
| 21 | `previewZoom` | `1.000` | (не превью) |
| 22–23 | `previewVehicleColour1/2` | `-1 -1` | (не превью) |
| 24 | `text` | `1` | плейсхолдер редактора (не переносится — строку задаёт сервис) |

> **Внимание (для геймдизайнера, финал на ревью):** в пресете **`box = 0`
> (бокс выключен)** — при выключенном боксе полупрозрачная чёрная подложка НЕ
> рендерится, бар — только белый текст Pricedown. Если нужен визуальный
> бар-подложка, включить бокс (`layout.params.box = true`) — боксовый и фоновый
> цвета из пресета уже проставлены рядом, это правка одной строки.
>
> **Расхождение кода с пресетом:** в коде `outline = 1` (в пресете `0`) — по вердикту
> геймдизайнера бару нужен гарантированный контраст на светлом небе (верх-центр),
> где белый текст без подложки терялся бы. Бокс оставлен выключенным (при
> `textSize.x = 400` плашка растянулась бы почти на пол-экрана под 4–5 символов);
> контур глифов даёт контраст, не превращая бар в широкую плашку. Требует
> verify-on-client днём над светлым небом.

## API

```cpp
// Показать/обновить бар: остаток в секундах (+ опц. англ. метка).
m_screenTimer.show(player, remainingSeconds, "BOARDING" /* label = {} */);
m_screenTimer.hide(player); // погасить бар
```

- `remainingSeconds` — остаток, который бизнес держит сам. `<= 0` → защитный
  авто-hide (бизнес запушил истёкший остаток — гасим бар, не показываем «0» и не
  уходим в отрицательные значения).
- `label` — **опциональная** метка перед числом, **ТОЛЬКО English** (конвенция
  экранных надписей). Пусто — только число.

**Формат текста** (языко-нейтральный, финал на ревью геймдизайнера): числовой остаток
`M:SS` (`0:30`, `0:29`, …, `0:01`); с меткой — `LABEL M:SS` (`BOARDING 0:29`).

## Поведение — обновление без мигания

Один персистентный per-player textdraw на игрока, лениво создаётся при первом `show()`
и переиспользуется:

- **Первый `show()`** — `createForPlayer` (макет + строка) + `show()`.
- **`show()` на уже показанном баре** — обновляется **ТОЛЬКО строка**
  (`setTextForPlayer` → `IPlayerTextDraw::setText`, лёгкий `PlayerTextDrawSetString`
  RPC на клиент, свойства макета не трогаем). Полного рестрима/`show()` нет — **бар не
  мигает** каждую секунду. (В open.mp `PlayerTextDraw::setText` при показанном
  textdraw сам шлёт SetString — проверено по `Server/Components/TextDraws/textdraw.hpp`.)
- **`show()` после `hide()`** — `setText` (кладёт строку в память, скрытый textdraw
  клиенту не шлёт) + `show()` (пересылает textdraw целиком с новой строкой).
- **`hide()`** — `IPlayerTextDraw::hide()`, идемпотентна (скрытый бар — no-op).

Один слот на игрока: новый `show()` (в т.ч. со сменой метки) заменяет предыдущий
текст в том же баре. Сервис сам НЕ тикает и НЕ гасит по нулю сам по себе — гашение по
нулю только защитное (см. `remainingSeconds <= 0`), штатно окно закрывает бизнес
своим `hide()`.

## Дисконнект

Per-player textdraw умирает вместе с пулом игрока — `destroy` не требуется.
`ScreenTimerSystem::onPlayerDisconnect` → `resetPlayer` сбрасывает сохранённое
состояние (id textdraw + флаг показа), чтобы переиспользованный id следующего игрока
не унаследовал чужой textdraw. БД/persist нет (состояние сессионное).

## Потребители

- **BusJobSystem** — три окна смены водителя автобуса (см. `Docs/BusJob.md`):
  посадка (`BOARDING`, 30 с), возврат за руль (`RETURN`, 30 с), остановка (`BUS STOP`,
  10 с). Остаток пушится из существующего per-second тика депо (новых таймеров нет).

## Три правила

- **Читер-абуз.** Чистая косметика: сервер → клиент, никакой игровой логики от бара
  не зависит. `show(remainingSeconds)` вызывается бизнесом на **серверный** остаток
  (BusJob держит счётчики окон сам, клиенту не верит) — сам сервис клиентского ввода
  не принимает. Нагрузка структурно ограничена: один видимый textdraw на игрока,
  спам `show()` очередь не растит.
- **Краш-безопасность.** `playerId` — bounds-чек перед доступом к массиву состояний.
  `createForPlayer` может вернуть `nullptr` (пул per-player textdraw исчерпан) — бар
  тихо не показывается, `textDrawId` остаётся `-1`. Все доступы к textdraw через
  `getForPlayer` (null-safe). Состояние сбрасывается на дисконнекте — не работаем с
  чужим/протухшим id. Сервис не держит таймеров (тикает бизнес) — ре-энтрантности нет.
- **Перф.** Событийно/по пушу бизнеса, не per-tick сервиса. Обновление показанного
  бара — O(1): один SetString RPC + локальная строка `fmt` (аллокация локальной
  строки допустима, только у игроков с активным окном; `hide()` скрытого — no-op без
  RPC/аллокаций). Textdraw создаётся лениво один раз и переиспользуется.
