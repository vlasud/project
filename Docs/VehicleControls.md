# Управление машиной (билды водителя)

Код: `Src/Systems/Core/VehicleControlSystem`, `Src/Services/Core/VehicleService`
(`setEngine`/`setLights`), `Src/Services/Core/PlayerKeyService` (детекция фронта
клавиш).

## Что делает

Водитель переключает у СВОЕЙ машины:

| Билд | Клавиша (бит) | Физическая клавиша в машине | Действие |
|----|----|----|----|
| Двигатель вкл/выкл | `Action` (1) | левый Ctrl (также ALT GR / NUM0) | тоггл `params.engine` через `VehicleService::setEngine` |
| Фары вкл/выкл | `Fire` (4) | ЛКМ (также левый Alt) | тоггл `params.lights` через `VehicleService::setLights` |

Срабатывает только когда игрок — ВОДИТЕЛЬ (серверный стейт: `getSeat == 0` и
`getVehicle != null`). Пассажир и пеший игрок нажатием ничего не меняют. Чужую
машину тронуть нельзя — гейтинг по серверной правде `VehicleService`.

## Маппинг клавиш

Биты — классические значения SA (`SDK/values.hpp`, `enum Key`; зеркалит
`PlayerKeyService::Key`). Сервер open.mp — чистый релей: поле `Keys` из синка
декодируется одинаково для пешего, водителя и пассажира (`Server/Source/player_pool.hpp`),
никакого ремаппинга по стейту вождения нет. Какой бит ставит та или иная
физическая клавиша — решает клиент GTA:SA, и набор за рулём отличается от пешего
(тот же бит = разная клавиша по контексту; в `values.hpp` это видно по `AIM = HANDBRAKE`).

За рулём левый Ctrl и ЛКМ ставят **разные** биты (таблица клавиш open.mp:
<https://open.mp/docs/scripting/resources/keys>), поэтому разводятся без
клиентских модов:

- **двигатель** — `Action` (1): в машине этот бит ставят левый Ctrl, ALT GR и
  NUM0;
- **фары** — `Fire` (4): в машине этот бит ставят ЛКМ и левый Alt (drive-by
  огонь). На ноге `Fire` ставится ЛКМ/Ctrl, но обработчик гейтится стейтом
  водителя, так что пеший огонь ничего не переключает.

Известный компромисс: у водителя с drive-by оружием каждый зажим ЛКМ (выстрел)
одновременно тогглит фары — бит один и тот же, сервер по синку их не различит.

## Тоггл и трактовка авто-режима (-1)

`params.engine`/`params.lights` имеют три значения: `-1` — клиентский авто-режим,
`0` — выкл, `1` — вкл. Текущее состояние читается из `vehicle.getParams()` и
инвертируется:

- **двигатель**: `-1` (авто) трактуем как «работает» — заведённая машина это
  норма, первое нажатие её глушит (`engine != 0` → считаем включённым);
- **фары**: `-1` (авто) трактуем как «выключены» — первое нажатие включает
  (`lights == 1` → считаем включённым).

## Взаимодействие с «заглохла» и пустым баком

Двигатель переключается через `VehicleService::setEngine`, который НЕ заводит
заглохшую машину (HP добито к порогу пожара — нужен `repair()`) **и** машину с
пустым баком (`outOfFuel` — нужен `refuel()`; топливо см. `Vehicles.md`). Значит
нажатие «двигатель» на добитой/пустой машине не оживит её: тоггл «вкл» уйдёт в
`setEngine(on=true)` и выйдет без действия. Заглушить уже заглохшую/пустую — без
эффекта. Это разные флаги с разными «снятиями» (repair vs refuel).

Фары независимы от «заглохла» (`setLights` без ограничения): их можно включать и
на добитой машине.

## Три правила

- **Читер-абуз:** клавишу как клиентский ввод валидировать нельзя, но ДЕЙСТВИЕ
  гейтится серверно — переключаем только двигатель/фары машины, водителем которой
  игрок реально является (`getSeat == 0` + `getVehicle`). Чужую машину не тронуть.
  Спам нажатий отсекает антиспам `PlayerKeyService` (debounce 150 мс).
- **Краш:** не за рулём / нет машины — обработчик выходит (`nullptr`-чек);
  `playerId` валидируется внутри `VehicleService` (границы пула).
- **Перф:** обработчик событийный (фронт клавиши), не per-tick;
  `getParams`/`setParams` — O(1), без аллокаций в горячем пути.
