# Попап названия машины при посадке за руль

При посадке водителя в машину показывается название машины на едином
экранном textdraw через `ScreenNoticeService` (белый цвет, макет — низ-право
экрана, см. `Docs/ScreenNotice.md`). Native GameText не используется — в этом
сетапе он неуправляем (нет компонента `Fixes`, см. `Docs/ScreenNotice.md`).
Бизнес-фича (не Core).

Код: `Src/Systems/VehicleNameSystem/VehicleNameSystem.{h,cpp}`. Зависимости из
регистра сервисов (core): `VehicleService`, `ScreenNoticeService`. Регистрация —
`Src/Systems/SystemRegister.cpp`, сразу после `VehicleSystem` (bindOccupant уже
проставил водителя на смене стейта — `VehicleService::getVehicle(playerId)`
видит машину).

## Механика

- **Триггер** — `onPlayerStateChange(player, newState, oldState)` с
  `newState == PlayerState_Driver`. Пассажиры (любой другой сид) и прочие смены
  стейта попап не получают и не трогают.
- **Источник имени.** Машина водителя — `VehicleService::getVehicle(playerId)`;
  `nullptr` (рассинхрон стейта — машину уже уничтожили, событие ещё не дошло) —
  ничего не показываем. Имя модели — `VehicleService::getModelName(vehicle->getID())`;
  пустая строка (мусорная/неизвестная модель — на реальной машине водителя
  практически не бывает) — тоже ничего не показываем, лишь бы не рисовать пустой
  попап.
- **Показ.** `ScreenNoticeService::show(player, StringView(name.data(), name.size()), SHOW_TIME, Colour::White())`
  — сервис сам санитизирует текст (через `TextDrawService`: длина, управляющие
  символы, парность `~`). Имена машин — ASCII (cp1251-идентичны), поэтому
  показываем `string_view` из каталога БЕЗ копии и без `utf8->cp1251` конвертации.
- **Погасание — строго по серверному таймеру.** `ScreenNoticeService` сам гасит
  попап через `SHOW_TIME` (per-player таймер, а не клиентская fade-анимация),
  если к этому моменту нет другого отложенного сообщения (см.
  `Docs/ScreenNotice.md`). Повторная посадка (или любой другой попап,
  показанный ≥1с назад) перерисовывает текст мгновенно, без мигания.

## Константы баланса

| Константа             | Значение | Смысл                                   |
|------------------------|----------|------------------------------------------|
| `SHOW_TIME`            | `1000 ms`| длительность попапа (равна `ScreenNoticeService::MIN_DISPLAY` — гарантированно не будет вытеснен раньше своего срока) |
| Цвет                   | белый (`Colour::White()`) | параметр вызова `show()` |

## Три правила

- **Читер-абуз.** Попап — чисто косметика: сообщение сервер -> клиент, никакая
  серверная логика/анти-чит/начисления от него не зависят. Показ завязан на
  серверный факт (`VehicleService::getVehicle` + `getModelName`, не клиентское
  заявление). Многократный вход/выход из машины лишь перепоказывает попап на
  общем экранном textdraw игрока — серверной стоимости кроме самого события
  смены стейта нет; очередь `ScreenNoticeService` структурно не растёт (глубина
  pending — 1, последний вызов побеждает).
- **Краш-безопасность.** `playerId` bounds-чек (`0..MAX_PLAYERS`) перед доступом
  к сервисам. `getVehicle` под null-проверкой (нет машины — просто return).
  `getModelName` возвращает `string_view` на статические данные сервиса — пустая
  строка (не разыменование) для неизвестной модели, тоже гард на `.empty()`.
  Зависимости — только источники правды/Core-сервисы (`VehicleService`,
  `ScreenNoticeService`), сырой SDK не вызывается.
- **Перф.** Событийно (`onPlayerStateChange`), без per-tick тика. На
  срабатывание — O(1): один `getVehicle`, один `getModelName` (lookup по
  таблице), один `show` (textdraw создаётся лениво один раз на игрока и дальше
  переиспользуется, + отложенный `hide` по таймеру сервиса). Имя показывается
  как `string_view` из статического каталога — без аллокаций на этом пути
  (санитизацию в свой буфер делает `TextDrawService`).
