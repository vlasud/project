# Владение оружием (Weapon Proficiency)

Код: `Src/Services/WeaponProficiencyService`, `Src/Systems/WeaponProficiencySystem`.
Хук выстрела: `Src/Systems/Core/PlayerWeaponSystem/PlayerWeaponSystem.cpp`.
Связка с нативным skill: `Src/Services/Core/WeaponSkillService` (применение через
него, мост — в `WeaponProficiencySystem`).
Схема БД: `Sql/weapon_proficiency.sql` (`player_weapon_skill`).

## Что это

Кастомный стат прогрессии аккаунта: насколько хорошо игрок «владеет» конкретным
оружием. Нарабатывается стрельбой, растёт от 0 до 100.

**Не путать с нативным SA-MP weapon skill** (`Src/Services/Core/WeaponSkillService`):
тот — игровой навык 0..999, влияет на разброс/отдачу/дуал-вилд и живёт в игре.
Здесь — отдельный кастомный стат, хранится в своей таблице. Эти два стата
**связаны** (см. «Связь с нативным weapon skill» ниже): владение проецируется на
нативный уровень, чтобы прокачка реально улучшала стрельбу.

## Учитываемые оружия (ровно 5)

| Оружие | Серверный weapon id |
|----|----|
| Desert Eagle | 24 |
| Дробовик (простой) | 25 |
| AK-47 | 30 |
| M4 | 31 |
| Снайперская винтовка | 34 |

Выстрелы из любого другого оружия прогрессию не двигают.

## Механика прогрессии

- Скилл каждого оружия — целое в диапазоне **0..100**. По умолчанию 0 (нет строки
  в БД = 0).
- Каждые **`SHOTS_PER_SKILL[weapon]` валидных выстрелов** из оружия → **+1** к
  скиллу этого оружия. Порог **настраивается пер-оружие** (см. ниже), стартовые
  значения — **5** для всех (прежнее единое поведение). Кап — **100** (на капе
  остаток выстрелов больше не копится).
- Остаток выстрелов (0..`SHOTS_PER_SKILL[weapon]`-1, недобор до следующего +1)
  копится только в памяти и **не персистится** — теряется на логауте (так
  задумано: дешевле, чем писать счётчик при каждом выстреле).

### Настройка темпа прокачки (пер-оружие)

Порог «выстрелов на +1» задаётся **в одном явном месте** —
`Src/Services/WeaponProficiencyService/WeaponProficiencyService.h`, таблица:

```cpp
static constexpr std::array<int, WEAPON_COUNT> SHOTS_PER_SKILL = {5, 5, 5, 5, 5};
```

Индекс = `weaponIndex()`: **0** Desert Eagle, **1** Shotgun, **2** AK-47,
**3** M4, **4** Sniper Rifle. Чтобы изменить темп конкретного оружия — поправь
его число в этой таблице и **пересобери** (compile-time константа). Каждое
значение **должно быть >= 1**: 0 дал бы +1 скилл на каждый выстрел (баланс-мусор,
не краш). Стартовые `{5, 5, 5, 5, 5}` повторяют прежний единый порог — баланс не
меняется, пока значения не настроят.

## Что считается «выстрелом» (анти-чит)

Инкремент происходит **только на серверно-валидном выстреле** — в
`PlayerWeaponSystem::handleShot`, в ветке `!outcome.drop`. Все фейковые выстрелы
(NaN-данные пули, origin spoof, стрельба из невыданного оружия, ammo hack,
rapid-fire, silent aim) валидатор `PlayerWeaponService::onShot` помечает
`drop == true` и до прогрессии они не доходят. Оружие берётся из серверного
`bulletData.weapon`. Накрутить скилл фейковыми RPC нельзя.

## Жизненный цикл и персист

- **Коннект/дисконнект** — слот игрока сбрасывается в нули (`resetPlayer`), чтобы
  скилл одного аккаунта не утёк следующему игроку в том же playerId-слоте.
- **Старт сессии** (`subscribeStart`) — асинхронная загрузка из
  `player_weapon_skill` (`selectQuery` + serial-guard, как
  `FactionSystem::loadMembership`). Значения клампятся в 0..100 при раскладке в
  сервис.
- **Конец сессии** (`subscribeEnd`) — UPSERT всех 5 скиллов одним `throwQuery`
  (`ON DUPLICATE KEY UPDATE skill = VALUES(skill)`, как в `BankService`). В БД на
  каждый выстрел/каждый +1 НЕ пишем — это hot path стрельбы.

## Связь с нативным weapon skill

Владение проецируется на нативный SA-MP weapon skill
(`Src/Services/Core/WeaponSkillService`, 0..999): чем выше владение, тем меньше
разброс/отдача и быстрее перезарядка реально в игре. Применяется **только через
`WeaponSkillService::setLevel`** (его массив — источник правды нативных уровней),
клиент напрямую не дёргается.

**Маппинг оружие → нативная категория** (`PlayerWeaponSkill_*`, сверено с
`ThirdParty/open.mp-sdk/include/player.hpp`):

| Владение (weapon id) | Нативная категория |
|----|----|
| Desert Eagle (24) | `PlayerWeaponSkill_DesertEagle` |
| Дробовик (25) | `PlayerWeaponSkill_Shotgun` |
| AK-47 (30) | `PlayerWeaponSkill_AK47` |
| M4 (31) | `PlayerWeaponSkill_M4` |
| Снайперская винтовка (34) | `PlayerWeaponSkill_Sniper` |

**Маппинг уровня** (линейно): `level = proficiency * MAX_SKILL_LEVEL / MAX_SKILL`,
т.е. `0..100 → 0..999` (100→999, 50→499, 0→0). `setLevel` всё равно клампит
0..999.

**Когда применяется** (обе точки событийные, НЕ на каждый выстрел):
- **На загрузке владения** из БД (`loadProficiency`, после раскладки скиллов) —
  по всем 5 оружиям сразу.
- **На level-up (+1)** — `WeaponProficiencyService` отдаёт сигнал
  `subscribeLevelUp(playerId, weaponId, newSkill)`, на который подписан
  `WeaponProficiencySystem` и применяет нативный уровень одного изменившегося
  оружия. Сигнал срабатывает раз в `SHOTS_PER_SKILL[weapon]` выстрелов, поэтому
  `registerShot` на обычной пуле остаётся O(1) и WeaponSkillService не трогает.

Кросс-сервисная связка живёт в **системе**: `WeaponProficiencyService` остаётся
без зависимости от `WeaponSkillService` (сервис не инжектит сервис).

**Спавн отдельно не хукается.** `WeaponSkillService` хранит свой массив-источник
правды и переприменяет его на каждом спавне (`WeaponSkillSystem::onPlayerSpawn`).
Мы пишем в этот массив через `setLevel` на load/level-up — значит выставленные
уровни переживают респавн без отдельного хука.

### Источник правды и команда `/wskill`

Для **5 учтённых оружий** источником нативного уровня становится владение: на
загрузке и на каждом level-up он перезаписывается из владения. Дев-оверрайд
`/wskill` по этим 5 категориям (Deagle/Shotgun/AK47/M4/Sniper) — **временный**:
ближайший level-up или следующий вход (load) затрёт его значением из владения.
По остальным 6 категориям (Pistol/Silenced/SawnOff/SPAS12/Uzi/MP5) `/wskill`
остаётся единственным источником и владением не управляется.

## Где константы

`Src/Services/WeaponProficiencyService/WeaponProficiencyService.h`:

| Константа | Значение | Смысл |
|----|----|----|
| `MAX_SKILL` | 100 | потолок скилла |
| `WEAPON_COUNT` | 5 | размер per-player массивов и таблицы порогов |
| `SHOTS_PER_SKILL` | `{5, 5, 5, 5, 5}` | выстрелов на +1, **пер-оружие** (индекс = `weaponIndex`: 0 Deagle, 1 Shotgun, 2 AK-47, 3 M4, 4 Sniper); каждое значение >= 1 |
| `WEAPON_DEAGLE/SHOTGUN/AK47/M4/SNIPER` | 24/25/30/31/34 | учитываемые weapon id |

Набор учитываемых оружий продублирован для итерации в
`WeaponProficiencySystem.cpp` (`TRACKED_WEAPONS`) — при изменении пятёрки править
оба места.

## Производительность

`registerShot` — hot path (каждая пуля): O(1) (switch weapon→индекс), без
аллокаций, без обращений к БД. Состояние — два `std::array<int, 5>` на игрока в
`std::array<…, MAX_PLAYERS>`.
