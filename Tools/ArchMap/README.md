# Карта архитектуры

Одностраничное приложение, чтобы видеть проект «сверху»: какие есть системы и сервисы,
чем они связаны, какими числами настроены и что из этого видит игрок.

## Как пользоваться

```bash
python Tools/ArchMap/generate.py
```

и открыть `Tools/ArchMap/index.html` в браузере (двойным кликом, сервер не нужен).

Перегенерировать нужно **после каждой заметной правки кода** — карта собирается из
исходников и иначе показывает вчерашний проект. Генератор проставляет версию в тег
`<script>`, поэтому браузер не подсунет закэшированные данные.

## Разделы

| Раздел | Зачем |
|---|---|
| **Обзор** | Счётчики плюс три вопроса, которые обычно и решают, куда двигать проект: узлы риска (на них опирается больше всего кода), фичи без документации, самые крупные модули. Внизу — самостоятельные фичи игрока: у них нет зависящих модулей, их безопаснее всего трогать |
| **Карта связей** | Граф зависимостей. Размер узла — сколько модулей на него опирается. Наведение подсвечивает соседей, клик открывает панель модуля |
| **Модули** | Таблица со всем сразу: описание, число зависимостей, команд, настроек, строк. Поиск идёт и по описаниям, и по командам |
| **Команды** | Всё, что может ввести игрок, по разделам `/help`. Фактически — список возможностей проекта |
| **Настройки** | Все балансовые числа в одном месте: цены, тарифы, радиусы, таймауты, потолки. По умолчанию только бизнес-слой — Core сюда добавляет технический шум |
| **Данные** | Таблицы БД с колонками и тем, кто с ними работает; документация и модули, которые она описывает |

Панель модуля (клик по любому имени где угодно) показывает описание из шапки заголовочного
файла, зависимости в обе стороны, команды, регистрации в чужих реестрах, точки подключения
(старт сессии, таймеры, диалоги), таблицы БД, доки и все настройки.

## Откуда берутся данные

Карта **собирается из кода**, а не пишется руками, — нарисованная схема разъезжается с
проектом на первой же правке. Генератор опирается на конвенции проекта:

| Что | Откуда |
|---|---|
| модуль | папка в `Src/Services` или `Src/Systems` с парой `X.h`/`X.cpp` |
| слой | Core, если путь содержит `/Core/` |
| описание | блок `//` прямо над `class X` |
| зависимости | `getService<X>()` и члены вида `XService &m_...` |
| настройки | `static constexpr` в заголовке и `constexpr` в анонимном namespace `.cpp`; пояснение — комментарий в конце строки или блок над ней |
| команды | `add("имя", ..., "описание", HelpCategory::Категория)` |
| саморегистрация | `registerItem`, `addGood`, `addService`, `registerDispatch`, `registerType` |
| таблицы БД | `getTable("x")` и SQL-строки, сверенные со схемой |
| документация | док привязывается к модулю, если упоминает его имя |

Отсюда два следствия. Первое: **качество карты зависит от качества комментариев** — блок
над классом и есть то, что вы читаете в панели модуля. Второе: если модуль не соблюдает
конвенцию (например, класс лежит не в одноимённой папке), в карту он не попадёт.

## Файлы

- `generate.py` — сборщик; читает `Src/`, `Docs/`, `Sql/`
- `data.js` — выгрузка (`window.ARCH`); генерируется, руками не править
- `index.html` — приложение; без внешних зависимостей, работает офлайн с `file://`

`data.js` имеет смысл держать в репозитории: тогда карта открывается сразу после клона,
без запуска Python.
